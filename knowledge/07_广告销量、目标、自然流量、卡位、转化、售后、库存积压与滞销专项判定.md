# 业务巡检Agent知识库 - 切片 07：广告销量、目标、自然流量、卡位、转化、售后、库存积压与滞销专项判定

本切片定义所有专项严重度规则，包括 ACOS、广告花费、销量、目标偏离、自然流量、卡位、链接转化率、评分、退款、放量未执行、库存积压和滞销异常。输入是各专项指标的历史基线、连续窗口、样本量和数据完整性条件，输出是对应异常是否成立以及 S0/S1/S2 分级。

### 3.6 广告与销量类异常专项判定（ACOS / 广告花费 / 销量）

广告类异常以产品近 7 天平均 ACOS、近 7 天平均花费为基线（由系统按历史数据计算、随标签抓取）；销量类异常以过去 7 天日均销量为基线。判定结果为异常严重度，作为基础分进入打分。

触发前提：ACOS、广告花费、销量异常均需连续 ≥3 天满足下表偏离条件才触发，避免单日波动误报；连续天数越长、偏离越大，严重度越高。

（1）ACOS 类异常

ACOS 异常样本量前置规则：ACOS 异常在满足”实际 ACOS 连续 ≥3 天超出近 7 天平均 ACOS”的基础上，还必须满足最低样本量条件，才输出正式异常。最低样本量满足以下任一条件即可：① 近 3 天累计广告花费 ≥ 近 7 天日均花费 × 3 × 50%；② 近 3 天累计点击 ≥ 20 次。若连续 ≥3 天 ACOS 超标但不满足最低样本量条件，则不输出正式 ACOS 异常，仅标记为”ACOS 样本不足观察”。

| 实际 ACOS 相对近 7 天平均 ACOS（连续 ≥3 天） | 异常严重度 |
| --- | --- |
| 超出 0–30% | 不预警（正常波动） |
| 超出 30–60% | S2 |
| 超出 60–100% | S1 |
| 超出 >100% | S0 |

（2）花费超出

| 实际花费相对近 7 天平均花费（连续 ≥3 天） | 异常严重度 |
| --- | --- |
| 超出 0–30% | 不预警 |
| 超出 30–50% | S2 |
| 超出 50–100% | S1 |
| 超出 >100% | S0 |

（3）花费不足

| 实际花费较近 7 天平均花费下降幅度（连续 ≥3 天） | 异常严重度 |
| --- | --- |
| 下降 <30% | 不预警 |
| 下降 30–50% | S2 |
| 下降 >50% | S1 |

（4）销量异常 / 销量增长提示（基准：过去 7 天日均销量）

下降方向：

| 当前销量 / 近 7 天日均（连续 ≥3 天） | 异常严重度 |
| --- | --- |
| 70%–100%（降幅 <30%） | 不预警（正常波动） |
| 50%–70% | S2 |
| 30%–50% | S1 |
| <30% | S0 |

上升方向（销量增长提示，封顶 S1）：

| 当前销量 / 近 7 天日均（连续 ≥3 天） | 异常严重度 |
| --- | --- |
| 100%–150%（涨幅 <50%） | 不预警 |
| 150%–200% | S2 |
| >200% | S1 |

判定说明：近 7 天平均 ACOS / 平均花费由系统按该产品过去 7 天历史数据计算并随标签抓取，本系统直接使用；不依赖人工设定的目标值。

受广告目的调节：盈利型花费超出更敏感可上调；引流型 / 推进期花费不足更值得关注可上调；维持 / 清货期容忍度高可下调。

严重度不对称：花费超出是直接花费损失，最高可达 S0；花费不足主要是机会成本，默认封顶 S1。销量同理——下降是损失型可达 S0，上升方向输出为”销量增长提示”，属于机会提示型封顶 S1。

原”广告消耗断量”场景暂不纳入判定。清货阶段产品（liquidating）的广告调整 AI 仅可建议、必须人工确认，对应方案”必须人工介入”属性。

### 3.7 目标偏离专项判定（基准：ERP 运营设定的日均目标单量 / 月目标）

目标偏离衡量”实际单量是否达到运营设定目标”，与销量异常（和自身近 7 天比”变化”）相互独立、互为补充：一个产品可能销量稳定却长期不达标（销量异常不报、目标偏离报）。采用三窗口判定：

| 时间窗口 | 比什么 | 基准 | 作用 |
| --- | --- | --- | --- |
| 当日 | 当日单量 vs 日均目标 | 日均目标单量 | 发现即时偏离，仅观察，不预警 |
| 近 3 天 | 近 3 天日均 vs 日均目标 | 日均目标单量 | 连续偏离才判定为异常 |
| 近 7 天 | 近 7 天日均 + 月累计完成率 vs 月目标节奏 | 日均目标 + 月目标 | 判断趋势性偏离、是否影响月目标达成 |

严重度分档（与销量异常档对齐；近 3 天连续偏离才进入分档）：

| 实际 / 日均目标（近 3 天连续） | 异常严重度 |
| --- | --- |
| ≥70%（差 <30%） | 不预警（正常波动） |
| 50%–70% | S2 |
| 30%–50% | S1 |
| <30%，或近 7 天持续偏离（近 7 天内逐日实际单量均低于日均目标，连续 7 天），或月累计完成率 / 月时间进度 <50% | S0 |

说明：仅当日偏离、近 3 天未连续的，不处理（不预警）。目标单量由 ERP 运营设定并抓取，本系统直接使用。月累计完成率 / 月时间进度 <50% 为”月目标严重落后”的初始判断口径，可在影子期 / 运营反馈后校准。

### 3.8 自然流量异常专项判定（基准：近 7 天平均自然订单占比）

自然订单占比 = 自然订单 / 总订单。占比下降反映自然流量健康度走弱；即使总销量被广告补足、看似稳定，自然这条腿仍可能在恶化。采用三窗口判定：

| 时间窗口 | 看什么 | 作用 |
| --- | --- | --- |
| 当日 | 当日自然订单占比 vs 近 7 天平均 | 即时下滑，仅观察，不预警 |
| 近 3 天 | 近 3 天平均占比连续低于近 7 天平均 | 连续偏离才判定为异常 |
| 近 7 天 | 近 7 天占比走势是否持续下行 | 判断趋势、确认慢性恶化，升级严重度 |

被动下降边界：若自然订单数未下降，只是总订单上涨导致自然占比被动下降，不直接按”自然单下滑型”处理；应进入模块 6.0.8 的”自然 vs 广告关系”查证，区分是否属于”增长依赖广告，自然没跟上”，或自然单也同步增长、只是广告增长更快导致占比下降。

严重度分档（自然占比下降幅度，vs 近 7 天平均，连续 ≥3 天）：

| 自然占比下降幅度 | 异常严重度 |
| --- | --- |
| <10 个百分点 | 不预警（正常波动） |
| 10–20 个百分点 | S2 |
| 20–35 个百分点 | S1 |
| >35 个百分点，或近 7 天持续下行（近 7 天内逐日自然占比均低于近 7 天平均基线，连续 7 天） | S0 |

注：档位数值为初值，可在影子期 / 运营反馈后直接调整。自然流量异常与销量异常相互独立——销量看总单量变化，自然流量看自然占比；它也是”目标偏离”原因查证中”流量减少”项所指向的异常。

### 3.9 卡位异常专项判定（基准：近 7 天平均卡位）

卡位 = 本产品在直接竞品集合中的排位（ERP 抓取，整数名次，数字越小越靠前）。当前卡位名次高于近 7 天平均卡位名次，即表示卡位下滑；卡位下滑 = 卡位名次数字变大，被竞品超过。下滑比例 =（当前卡位 − 近 7 天平均卡位）/ 近 7 天平均卡位；卡位为整数，下滑比例由当前整数卡位直接计算（如近 7 天均 5、当前 6 → 下滑 20%）。采用三窗口判定：

| 时间窗口 | 看什么 | 作用 |
| --- | --- | --- |
| 当日 | 当日卡位名次是否高于近 7 天平均卡位名次 | 即时下滑，仅观察，不预警 |
| 近 3 天 | 近 3 天平均卡位名次是否连续高于近 7 天平均卡位名次 | 连续下滑才判定为异常 |
| 近 7 天 | 近 7 天卡位名次是否持续变大 / 走势变差 | 判断趋势，升级严重度 |

严重度分档（卡位下滑比例，vs 近 7 天平均，连续 ≥3 天）：

| 卡位下滑比例 | 异常严重度 |
| --- | --- |
| <20% | 不预警（正常波动） |
| 20%–50% | S2 |
| 50%–100% | S1 |
| >100%，或近 7 天持续下行（近 7 天内逐日卡位名次均高于近 7 天平均基线，连续 7 天） | S0 |

注：档位数值为初值，可在影子期 / 运营反馈后直接调整。卡位异常是竞争入口层的上游信号，可能进一步导致自然流量异常、销量下滑，也是目标偏离 / 销量异常原因查证中可能指向的上游原因。

### 3.10 链接转化率异常专项判定（周维度，双基准）

口径：链接转化率 = 整条链接（父 ASIN）的订单商品总数 / 会话，链接级，不分变体。一周抓一次，周维度判定，不用三窗口。双基准任一触发即报，严重度取两者较高。已去掉原”由绿变红”判定。

空值不判定规则：若链接转化率字段为空、未生成、无法计算，或新品前期因数据未积累导致近 7 天 / 本周 / 上周转化率为空，则不触发链接转化率异常，也不进入 S0 / S1 / S2 分级；仅标记为”转化率数据为空 / 待数据积累”，不生成正式异常任务。注意：转化率为空不等于转化率为 0；若已有会话数据且系统计算出的转化率为 0，则属于有效数值，应继续按样本量门槛和双基准规则判定。

最低样本量规则：链接转化率异常需满足最低样本量后才输出正式异常。默认最低样本量：本周会话 ≥100；若用于本周 vs 上周比较，则本周和上周均需有有效会话数据。本规则中的”会话”对应业务报告中的会话字段，不使用”页面流量”作为转化率样本量基准。若本周会话 <100，但本周 + 上周订单商品总数 ≥10，可进入观察判断；若转化率下降明显，仅输出”转化率样本不足观察”，不进入正式 S0 / S1 / S2 分级。

基准 A：本周 vs 上周（自身变化）

| 本周转化率较上周降幅 | 异常严重度 |
| --- | --- |
| <20% | 不预警（正常波动） |
| 20%–50% | S2 |
| 50%–80% | S1 |
| >80% | S0 |

基准 B：本周 vs 类目平均转化率（是否低于同类）

| 本周转化率 / 类目平均转化率 | 异常严重度 |
| --- | --- |
| ≥80% | 不预警（接近同类水平） |
| 50%–80% | S2 |
| 30%–50% | S1 |
| <30% | S0 |

注：两个基准各算一个严重度，取较高者为最终严重度。档位数值为初值，可在影子期 / 运营反馈后直接调整。类目平均转化率由 ERP 直接提供；若字段缺失，按 3.4 全局字段缺失规则处理。

### 3.11 售后异常专项判定（评分 / 退款，双基准）

本节仅对评分异常、退款异常进行专项分级。近期集中差评不进入本节评分 / 退款专项分级；其触发口径见模块 2.7，默认严重度见 3.3。

评分异常（每日抓取，慢变量、不用三窗口；双基准任一触发即报、严重度取高）

评分异常空值规则：若当前评分为空、未生成，或新品前期尚未积累有效评分数据，则不触发评分异常，不进入 S0 / S1 / S2 分级；仅标记为”评分数据为空 / 待数据积累”。若当前评分已经生成，则无论评分数量多少，均可进入评分异常判定。新品早期评分数量少时，不作为降级或不判定理由，应在任务卡中标注”评分样本少，需重点读取评论内容确认产品质量问题”。

基准 A：当前评分 vs 近 7 天平均评分（评分下降幅度）

| 评分较近 7 天平均下降 | 异常严重度 |
| --- | --- |
| <0.1 分 | 不预警 |
| 0.1–0.3 分 | S2 |
| 0.3–0.5 分 | S1 |
| >0.5 分 | S0 |

基准 B：当前评分 vs 目标评分

| 评分相对目标评分 | 异常严重度 |
| --- | --- |
| ≥目标（达标） | 不预警 |
| 低于目标（含从达标跌破目标线） | S1 |

退款异常（一周抓一次、周维度，不用三窗口；双基准任一触发即报、严重度取高）

退款异常数据完整性规则：退款异常必须在本周与上周均存在正常退款率数据的情况下，才进行”本周 vs 上周”的环比判定。若上周退款率为空、未生成、无正常数据，或上周订单数据缺失，则不触发退款异常环比判定，不进入 S0 / S1 / S2 分级；仅标记为”退款数据不足 / 待补充”。

退款异常样本量规则：退款异常需满足最低订单样本量后才输出正式异常。默认最低样本量：本周订单商品总数 ≥20，或本周 + 上周订单商品总数 ≥30。若订单样本不足但退款率升高，仅输出”退款样本不足观察”，不进入正式 S0 / S1 / S2 分级。

基准 A：本周退款率 vs 上周（相对上升幅度）

| 本周退款率较上周相对上升 | 异常严重度 |
| --- | --- |
| <30% | 不预警 |
| 30%–60% | S2 |
| 60%–100% | S1 |
| >100% | S0 |

基准 B：本周退款率 vs 类目平均退换货率（倍数）

| 本周退款率 / 类目平均退换货率 | 异常严重度 |
| --- | --- |
| ≤1.2 倍 | 不预警 |
| 1.2–1.5 倍 | S2 |
| 1.5–2 倍 | S1 |
| >2 倍 | S0 |

注：各档数值为初值，可在影子期 / 运营反馈后直接调整。评分目标值、类目平均退换货率均由 ERP 提供；若字段缺失，统一按 3.4 全局字段缺失规则处理。

### 3.12 放量未执行专项判定（该做没做型，无需查证）

放量未执行 = 产品已满足全部放量条件、但广告未加投入（该放大却没放大）。与目标偏离形成闭环：未达标→目标偏离（查因修复）；达标且可放量却没放→放量未执行（提示放大）。下列 5 个条件全部满足即触发，默认严重度 S1。

销量增长提示是”销量正在上升”的前置信号，不等于放量未执行。只有同时满足销量达标、库存充足、ACOS 健康、自然占比上涨且广告未放量时，才触发放量未执行。若销量增长提示与放量未执行同时命中，优先输出放量未执行，销量增长数据作为判断依据展示。

| # | 放量条件 | 判定口径 |
| --- | --- | --- |
| 1 | 销量达标 | 连续 7 天日均销量 ≥ 日均目标单量 |
| 2 | 库存充足 | 可售库存 ≥ 日均单量 × 1.2 × 30（支撑放量后 1 个月，增幅 20%） |
| 3 | ACOS 健康 | 连续 7 天日均 ACOS < 目标 ACOS；近 7 天 ACOS 为空、未生成或广告样本不足时，不得直接判定为 ACOS 健康 |
| 4 | 广告未放量 | 近 3 天日均广告花费 ≤ 近 7 天平均花费 × 1.1 |
| 5 | 自然占比上涨 | 近 7 天平均自然订单占比 > 前 7 天平均自然订单占比，且近 3 天平均自然订单占比不低于近 7 天平均自然订单占比 |

数据不足边界：ACOS 健康必须基于有效广告数据判断；若近 7 天 ACOS 为空、未生成或广告样本不足，则不得输出正式”放量未执行”，仅标记为”放量机会待评估 / ACOS 数据不足”。

严重度：默认 S1（机会损失型——产品各项健康、自然流量加速向上却未放大，机会损失值得尽快处理）。处理建议：提示运营评估放量（加预算 / 扩词 / 加大投放），抓住上升势头。该点位无需原因查证（条件满足本身即结论）。各阈值（1.2、30、×1.1 等）为初值，可在影子期 / 运营反馈后直接调整。

### 3.13 库存积压专项判定（第一道：提前预警，可售天数 A + 目标累计 B 交叉）

库存积压属现象即原因型（不查证，直接给处理建议）。两个指标各自分档，再交叉取综合严重度。

数据完整性要求：库存积压正式判定前必须具备可售库存、近 30 天日均销量、未来 2–4 个月目标累计。若缺少未来 2–4 个月目标累计，则不得仅凭可售天数输出正式库存积压 S0/S1/S2，只能输出”库存压力待确认 / 数据不足”。可售天数用于判断当前库存压力，未来目标累计用于判断库存是否能被未来目标消化，两者必须交叉使用。

可售天数口径：可售天数 = 可售库存 ÷ 近 30 天日均销量。若上架不足 30 天，则按已上架有效销售天数计算，并标注”样本期较短”。若新品上架时间较短，或有效销售天数不足 7 天，不输出正式库存积压异常，仅标记为”新品库存压力待观察”。

日均销量为 0 的处理：若近 30 天日均销量为 0，且产品不是新品观察期，同时存在可售库存，则可售天数按”>120 天”处理，A 档判为 S0；若产品仍处于新品观察期，则不直接输出正式库存积压，标记为”新品库存压力待观察”。

A：可售天数（可售库存 ÷ 近 30 天日均销量）

| 可售天数 | A 档 |
| --- | --- |
| <60 天 | 不预警 |
| 60–90 天 | S2 |
| 90–120 天 | S1 |
| >120 天 | S0 |

B：目标累计（可售库存 vs 未来 N 个月目标累计，目标已含淡旺季）

| 可售库存覆盖 | B 档 |
| --- | --- |
| ≤未来 2 个月目标（本月 + 下月） | 不预警 |
| 2–3 个月目标 | S2 |
| 3–4 个月目标 | S1 |
| >4 个月目标 | S0 |

综合严重度（A、B 交叉）：

| A 可售天数 | B 未来目标累计 | 综合处理 |
| --- | --- | --- |
| A、B 均不预警 | A、B 均不预警 | 不输出库存积压。 |
| A、B 均有预警 | A、B 均有预警 | 取较高严重度。 |
| A 有预警 | B 不预警 | A 档降一档后输出，并提示复核未来目标是否可靠。 |
| A 不预警 | B 有预警 | B 档降一档后输出，并提示复核淡旺季和目标是否合理。 |
| A 或 B 关键数据缺失 | 任一关键数据缺失 | 不输出正式 S0 / S1 / S2，输出”库存压力待确认 / 数据不足”。 |

降档规则：S0 → S1；S1 → S2；S2 → 观察，不输出正式库存积压。

注：A 天数档（60 / 90 / 120）、B 月数档均为初值，可在影子期 / 运营反馈后调整。处理建议见模块 6.2（按 S2/S1/S0 给不同力度）。本异常的巡检频次由巡检频次规则文件统一维护；复查以运营设置时间优先，未设置时按默认复查规则执行。

### 3.14 滞销异常专项判定

滞销异常属现象即原因型（不查证，直接给处理建议）。针对已产生超龄仓租、短期无法消化、损失达规模的产品。它与库存积压不同：滞销看超龄那部分库存是否卖得掉，库存积压看整体可售库存撑多久。一个产品可整体库存健康却有超龄老货滞销。

计算层级：滞销异常先在子 ASIN / 变体层识别超龄库存与消化周期，再归集到父 ASIN 任务卡。父 ASIN 维度用于汇总单月超龄仓租费用和输出任务卡；父卡严重度取命中子 ASIN 中最高严重度。不同颜色 / 尺码库存不能互相消化，命中子 ASIN 的滞销库存应使用该子 ASIN 自身销量计算消化周期。

数据完整性要求：滞销异常正式判定前必须具备超龄库存量 / 滞销库存量、命中子 ASIN 近 30 天日均销量、单月超龄仓租费用、FBA 库龄 / 超龄状态。若缺少超龄库存量、单月超龄仓租费用或超龄状态，则不得触发正式滞销异常；不能用普通可售库存、库存积压结果或可售天数替代滞销判断。

消化周期口径：滞销库存消化周期 = 命中子 ASIN 滞销库存量 ÷ 命中子 ASIN 近 30 天日均销量。若命中子 ASIN 近 30 天日均销量 = 0，且存在滞销库存，则消化周期按 >120 天处理；若近 30 天日均销量为空、未生成或缺失，则按数据不足处理，不输出正式 S0 / S1 / S2。

准入条件（3 个全部满足才进入）：

| 准入条件 | 判定口径 |
| --- | --- |
| ① 有滞销库存 | 存在收取超龄仓租的库存（子 ASIN 查、父 ASIN 汇总）。 |
| ② 1 个月消化不完 | 命中子 ASIN 滞销库存 ÷ 命中子 ASIN 近 30 天日均销量 >30 天。 |
| ③ 超龄费达规模 | 父 ASIN 汇总单月超龄仓租费用 > $20。 |

严重度分级（按消化周期，只产出 S；定位权重 T、阶段、淡旺季由模块 4 统一打分施加）：

| 滞销库存消化周期（命中子 ASIN 滞销库存 ÷ 命中子 ASIN 近 30 天日均销量） | 严重度 |
| --- | --- |
| >30 天且 ≤60 天 | S2 |
| >60 天且 ≤120 天 | S1 |
| >120 天，或近 30 天日均销量 = 0 | S0 |

滞销异常与库存积压的共现去重规则：两者为独立异常，看不同库存维度（滞销看超龄部分卖不卖得掉、库存积压看整体可售库存撑多久），各自独立判定。但大多数情况下滞销产品也会触发库存积压，故定共现去重规则：

| 触发情况 | 处理 |
| --- | --- |
| 同时触发滞销异常 + 库存积压 | 取滞销异常作为主任务；库存积压不重复生成主任务、不重复计入打分，可作为关联库存压力在任务卡中展示。 |
| 仅触发滞销异常（整体不积压） | 正常报滞销异常。 |
| 仅触发库存积压（无超龄滞销） | 正常报库存积压。 |

理由：同时出现时，滞销是更具体、已发生实际损失的状态，取滞销可避免对同一批问题库存重复处理；库存积压为预测型风险，在滞销已暴露实际损失时不重复生成主任务。注：准入门槛（$20、30 天）为初值可调，处理建议见模块 6.2。本异常的巡检频次由巡检频次规则文件统一维护；复查以运营设置时间优先，未设置时按默认复查规则执行。
