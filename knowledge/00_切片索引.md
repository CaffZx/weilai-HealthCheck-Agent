## 4. 各切片详细说明

### 4.1 `01_模块0_关键术语.md`

**作用：** 作为全知识库的术语基座，约束 Agent 对 S、T、P 的理解。

**应在以下情况调用：**
- 需要解释异常严重度、产品定位、优先级的区别。
- 需要校验最终输出字段是否使用了正确字母体系。
- 后续模块出现 S0/S1/S2、T0—T3、P0/P1/P2 时需要回溯定义。

**不负责：** 不定义具体异常、不计算分值、不生成处理建议。

### 4.2 `02_模块1_异常字典.md`

**作用：** 作为异常识别和边界判断的主字典，回答“这是什么异常、属于哪一类、是否要查因”。

**应在以下情况调用：**
- 识别链接状态、内容、价格促销、库存、交易表现、合规属性、售后异常。
- 区分“变体掉线”与“父子体关系异常”等易混点位。
- 判断异常属于直接定因型还是待查原因型。

**关键输出：** 异常大类、具体点位、定义、边界、异常类型。

### 4.3 `03_模块2_严重度通用原则.md`

**作用：** 解释异常如何按链接级或变体级生效，以及严重度上调的适用条件。

**应在以下情况调用：**
- 判断异常命中父体整体还是具体子体。
- 确定应使用链接级基础分还是具体变体重要性列。
- 说明“初判 Sx，因多个待查因异常共同原因而上调”的逻辑。

**关键限制：** 严重度只描述异常本身，不掺入产品定位和变体重要性；分值计算由代码完成。

### 4.4 `04_模块3_查因与处理建议.md`

**作用：** 是 Agent 生成“原因说明 + 处理建议”的核心执行切片。

**内部功能分区：**
- `3.0`：待查因型异常的 root_cause 映射和兜底话术。
- `3.1`：处理建议的精确匹配、同点位补位和大类兜底顺序。
- `3.2`：直接定因型异常的具体处理建议。
- `3.3`：具体点位未命中建议表时的大类兜底。

**调用规则：**
- 交易表现异常、售后异常：优先进入 `3.0`，根据系统注入的 root_cause 输出。
- 直接定因型异常：跳过 `3.0`，直接进入 `3.2`。
- `3.2` 没有精确建议：按 `3.1` 的三级规则处理，最终可使用 `3.3`。
- root_cause 为 null：只能使用对应小节的兜底话术，不得自行编造原因。

### 4.5 `05_模块4_运营输出规范.md`

**作用：** 将前面模块形成的判断结果组织成运营可直接执行的任务卡。

**应在以下情况调用：**
- 输出父 ASIN 任务卡。
- 确保定位信息、优先级信息和异常明细字段齐全。
- 判断哪些异常需要原因字段，哪些不需要。
- 展示豁免、共因去重、共因上调和关联现象。

**关键限制：** 不负责重新判断异常和计算分值，只负责按既定结果规范化表达。

## 5. Agent 检索路由

| 当前任务 | 优先检索切片 | 后续检索切片 |
|---|---|---|
| 不清楚 S/T/P 的含义 | 模块 0 | 无 |
| 识别异常名称、分类或边界 | 模块 1 | 模块 2 |
| 判断链接级/变体级、严重度或共因上调 | 模块 2 | 模块 1（核对点位定义） |
| 交易表现异常或售后异常需要查因 | 模块 3 的 3.0 | 模块 1、模块 4 |
| 直接定因型异常需要处理建议 | 模块 3 的 3.2 | 模块 3 的 3.1/3.3 |
| 建议表没有精确命中 | 模块 3 的 3.1 | 模块 3 的 3.3 |
| 生成最终运营任务卡 | 模块 4 | 模块 0—3 |

## 6. 推荐调用顺序

```text
模块 0：统一术语
   ↓
模块 1：识别异常及边界，区分直接定因型/待查原因型
   ↓
模块 2：确认作用层级、严重度解释与共因上调
   ↓
模块 3：完成原因说明、处理建议和兜底
   ↓
模块 4：生成规范化运营任务卡
```

## 7. 使用约束

1. 不得仅凭异常现象自行编造 root_cause。
2. 待查因型异常与直接定因型异常必须走不同路径。
3. 异常定义与边界以模块 1 为准，严重度与作用层级以模块 2 为准。
4. 处理建议优先使用模块 3 的精确条目，缺失时才允许补位或兜底。
5. 最终输出必须遵守模块 4 的字段标准，不得因优先级或异常类型删减固定字段。
6. 异常分值由系统计算并注入，LLM 不自行计算。
