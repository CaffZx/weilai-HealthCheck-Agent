## 模块 1　异常字典

本文档界定异常概念及边界、规定异常指标、确定异常类别。Agent 使用本字典理解异常语义，用于原因查证、原因说明与话术生成。

**异常分类总览：** 共 7 个异常大类。其中**交易表现类、售后异常类**为**待查原因型**（需匹配模块 3 原因查证），其余为**直接定因型**（直接出建议）。

| 序号 | 异常大类 | 指标 | 类型 |
|------|---------|------|------|
| 1 | 链接状态异常 | 链接能否正常展示/购买/销售、成交主导权 | 直接定因型 |
| 2 | 内容完整性异常 | 页面内容是否完整、能否承接流量转化 | 直接定因型 |
| 3 | 价格与促销异常 | 价格促销是否正常承接成交 | 直接定因型 |
| 4 | 库存与可售异常 | 库存能否支撑继续销售 | 直接定因型 |
| 5 | **交易表现异常** | 转化/销量/广告等结果指标 | **待查原因型** |
| 6 | 合规与属性异常 | 是否存在平台规则风险 | 直接定因型 |
| 7 | **售后异常** | 差评/评分/退款等售后信号是否影响买家信任与经营 | **待查原因型** |

### 1.1 链接状态异常

**定义：** 产品链接在前台展示、购买路径、在售状态、父子体结构或平台状态上出现异常，导致链接无法正常展示、无法正常下单，或存在影响正常销售的状态风险，或链接的成交主导权（Buy Box）异常。  
**边界：** 判断链接本身是否还能正常展示、正常购买、正常销售。

| 表现形式 | 定义 |
|---------|------|
| 链接不可售 | 链接前台无法作为正常在售商品展示，或后台状态不再属于正常可售范围。例如前台变狗、页面失效等；后台 ASIN 显示的字段为「不可售」 |
| 变体掉线 | 原本挂在父体下的单个或部分子体脱离父体，导致买家无法在父体变体中选择该子体，但父体结构整体仍存在。边界：只要父体结构仍在，不属于父体被拆；父体被拆归父子体关系异常。 |
| 父子体关系异常 | 父体被拆，全部子体从原父体结构中掉出，父体和子体关系异常，影响变体展示或销售。边界：仅当父体结构被拆散、全部子体掉出时归此点位；部分子体掉线归"变体掉线"，两不相容。 |
| Buy Box 丢失 | 商品未获得 Buy Box（链接仍在售，但未拿到黄金购物车，直接影响成交）。 |

### 1.2 内容完整性异常

**定义：** 产品链接页面中的核心内容出现缺失、错误、展示异常或审核异常，导致买家无法完整理解产品信息，进而影响点击、转化或页面承接能力。  
**边界：** 判断页面内容是否完整，是否具备承接流量和转化的基础。

| 问题点位 | 定义 |
|---------|------|
| 主图异常 | 状态可检测项：主图缺失、不符合平台规则被禁止显示、审核不通过或前台展示异常（以平台后台状态 / 展示抓取结果为判定依据）。 |
| 图片异常 | 副图数量＜3 张，副图未通过审核或展示异常。 |
| 标题异常 | 状态可检测项：标题缺失、审核不通过或不符合平台规则。 |
| 五点异常 | 五点缺失、数量不足五条、信息不完整。 |
| A+ 异常 | A+ 缺失、未展示或审核异常。 |

### 1.3 价格与促销异常

**定义：** 产品当前售价、Coupon、促销活动、折扣展示或活动价格出现异常，导致链接转化下降、利润异常、Buy Box 风险增加，或销售节奏受到影响。  
**边界：** 判断价格和促销是否正常承接流量，是否影响成交效率。

| 问题点位 | 定义 |
|---------|------|
| 变体价差异常 | 同一父 ASIN 下，各变体前台到手价差距明显偏离正常价格带，可能影响买家选择、链接动销、广告承接或主推变体转化。比价基准为主要色/流量入口颜色的主推尺码到手价。 |
| 促销异常 | ERP 系统活动配置存在但前台未展示对应促销信息；促销活动（秒杀、LD、Z 划算、Coupon 等）未生效、折扣错误，或前台展示与 ERP 配置的活动类型不一致。 |

### 1.4 库存与可售异常

**定义：** 产品库存状态、FBA 可售库存、库存承接能力或前台可购买状态出现异常，导致链接无法正常成交，或存在短期断货、推广无法承接的风险。  
**边界：** 判断库存是否能支撑链接继续正常销售。

| 问题点位 | 定义 |
|---------|------|
| FBA 可售库存为 0 | FBA 当前可售库存为 0，已无法承接后续销售，属于实际断货。 |
| 库存不足 | FBA 当前可售库存大于 0，但低于未来 14 天预计消耗（过去 7 天日均销量 ×14），存在短期断货风险。 |
| 库存积压 | 可售库存相对近期消化能力和未来目标消化能力明显偏高，存在库存占压、滞销或长期仓储费风险。具体按"可售天数 + 未来目标累计"双指标交叉判定。 |
| 滞销异常 | 已产生超龄仓租，且超龄库存短期无法消化、费用损失达到规模的库存异常。该点位只看超龄库存是否卖得掉，与库存积压看整体可售库存不同。子 ASIN 查、父 ASIN 汇总。 |

### 1.5 交易表现异常

**定义：** 链接在销量、订单、曝光、点击、转化率、广告成交、自然订单占比、卡位等经营指标上出现异常波动，说明链接当前流量获取能力、成交能力或流量承接能力出现问题。  
**边界：** 判断链接是否还能正常获得流量并完成成交。本类异常除放量未执行外均为待查原因型，现象不等于原因；触发后需进入模块 3 进行原因查证，确认真实原因后再输出处理建议。例外：放量未执行属直接定因型（条件满足本身即结论），不进入模块 3 查因，直接输出建议。

| 问题点位 | 定义 |
|---------|------|
| 链接转化率异常下降 | 链接转化率（整条链接，链接级）较历史水平或类目平均水平明显下降，说明链接成交承接能力变弱。按周维度判定。 |
| 销量异常 | 产品连续 3 天及 3 天以上，每天的实际销量都大于近 7 天日均销量。下降方向作为销量异常；上升方向作为"销量增长提示"。 |
| ACOS 异常 | 产品连续 3 天及 3 天以上，每天的实际 ACOS 都高于目标 ACOS，说明广告投入产出效率变差。 |
| 广告花费异常 | 产品连续 3 天及 3 天以上，每天的实际广告花费都偏离目标每日预算，包括花费超出和花费不足两个方向。 |
| 目标偏离 | 实际单量连续低于运营在 ERP 设定的日均目标单量或月目标节奏，说明当前销售结果未达到运营目标。 |
| 自然流量异常 | 自然订单占比连续 3 天及 3 天以上，每天的实际自然订单占比都低于近 7 天平均水平，说明链接自然流量贡献较弱。 |
| 卡位异常 | 本产品在直接竞品集合中的排位下滑，说明竞争入口位置变弱，可能进一步影响自然流量和销量。 |
| 放量未执行（直接定因型 — 不进入查因） | 产品已满足放量条件，但广告投入未跟上，属于"该做没做型"机会损失异常。 |

### 1.6 合规与属性异常

**定义：** 产品链接因类目、属性、平台规则、合规字段、认证要求、敏感表达或页面字段问题，存在被限制、被抑制、审核失败、下架或影响系统识别的风险。  
**边界：** 判断链接是否存在平台规则风险，是否会影响链接安全和系统识别。若问题表现为页面内容缺失、错图、标题 / 五点 / A+ 信息不完整，归内容完整性异常；若问题由平台规则、敏感表达、合规要求、类目 / 属性识别错误导致，归本类。

| 问题点位 | 定义 |
|---------|------|
| 类目异常 | 商品类目被错误修改，或类目与产品实际不匹配，影响平台识别、曝光或合规判断。 |
| 属性信息异常 | 颜色、尺码、材质、适用场景等属性缺失、错误或与产品实际不一致，影响系统识别、筛选曝光或买家理解。 |
| 合规异常 | 商品已经命中平台合规要求、认证要求、禁售/限售规则，或后台已有明确合规提示，需要修复后才能降低限制风险。作用层级为子体级（变体级），命中对象记录到具体子 ASIN。 |

### 1.7 售后异常

**定义：** 产品近期在差评、评分、退款等售后维度出现异常变化，可能影响买家信任、链接转化与长期经营。售后异常为待查原因型——现象（差评数 / 评分 / 退款率）不等于原因，需由 Agent 读取评论内容、退款理由等文字，归类出真实原因（尺码 / 质量 / 物流 / 页面描述等）。  
**边界：** 判断差评、评分、退款等售后信号是否已经影响或即将影响买家信任、链接转化与长期经营。售后异常只判断售后表现是否异常，具体原因需进入模块 3 读取评论内容或退款理由后确认。

| 问题点位 | 定义 |
|---------|------|
| 近期集中差评 | 满足以下任一条件即触发：① 14 天内新增低星（≤3 星）评论 ≥3 条，且其中 ≥60% 集中指向同一类问题（尺码 / 质量 / 物流 / 描述不符等，由 Agent 读取评论内容归类）。 ② 14 天内新增负面反馈数量 > 现有评分数的 20%。两个阈值（3 条、60%、20%）为初值，可在影子期 / 运营反馈后校准。|
| 评分异常 | 当前评分较近期平均评分下降，或低于运营设定的目标评分，说明买家信任信号变弱。按双基准判定。 |
| 退款异常 | 退款率较自身历史水平或类目平均水平明显升高，说明售后风险或产品承接问题上升。按周维度双基准判定。 |

> **🤖 LLM 注意：** 售后异常为**待查原因型**——现象不等于原因。系统检测到异常后注入判定结果，LLM 需读取评论内容、退款理由等文字，归类出真实原因（尺码/质量/物流/页面描述等），再根据 root_cause 匹配对应输出话术。
