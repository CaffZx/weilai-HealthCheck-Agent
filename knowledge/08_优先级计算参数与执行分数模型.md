# 业务巡检Agent知识库 - 切片 08：优先级计算参数与执行分数模型

本切片定义执行分数公式、异常基础分二维表、定位/阶段/淡旺季系数、并发权重、执行优先级阈值和同分破平规则。输入是模块 3 输出的正式严重度 S、模块 1 抓取的产品标签，以及模块 2 的作用层级和变体重要性，输出是产品执行分数和最终执行优先级 P0/P1/P2。

## 模块 4　优先级计算参数（配置表）

方案第五部分统一执行分数模型读取的全部参数集中于此，便于调参。修改本模块后 Agent 下次巡检即按新值计算。所有数值为初始建议值，需数据回流后校准。

### 4.0 执行分数公式（与方案第五部分一致）

单异常执行分数 = 异常基础分 × 定位系数 × 阶段系数 × 淡旺季系数

产品执行分数 = 最高单异常执行分数 + Σ(其余各异常执行分数 × 并发权重)

最终：按产品执行分数全局排序 → 按阈值映射执行优先级 P0/P1/P2

只有已经输出正式 S0 / S1 / S2 的异常，才进入模块 4 打分。数据不足、样本不足观察、转化率样本不足观察、新品库存压力待观察、放量机会待评估等观察类结果，不进入执行优先级打分。

打分只决定异常的初始执行优先级。超期不进打分——它由模块 5 升降级规则直接硬跳档（P1 满 7 天未处理→P0、P2 满 14 天未处理→P1），保证”拖太久必定升档”的确定性，而非靠加分。并发仍由打分体现（异常越多、产品执行分数越高，自然升档）。

### 4.1 异常基础分（严重度 × 变体重要性二维表）

基础分由异常严重度（S0/S1/S2）与异常作用层级 / 命中变体的重要性共同决定：链接级异常取”链接级异常基础分”列；变体级异常（含链接不可售、库存不可售、FBA 可售库存为 0、库存不足）按命中变体的主要色/次要色/长尾色取列。变体重要性已预乘进基础分，不再单列系数。

| 严重度 | 链接级异常基础分 | 变体级·主要色 | 变体级·次要色 | 变体级·长尾色 |
| --- | --- | --- | --- | --- |
| S0 | 100 | 100 | 70 | 25 |
| S1 | 60 | 60 | 42 | 15 |
| S2 | 30 | 30 | 21 | 8 |

取值规则：

- 链接级异常：发生在父体 / Listing 整体上的异常，取”链接级异常基础分”列；具体点位清单见模块 2.0，本节不重复罗列。

- 变体级异常：命中具体子体 / 变体的异常，按命中变体的重要性（主要色 / 次要色 / 长尾色）取列；具体点位清单见模块 2.0。

- 库存类异常（库存不可售、FBA 可售库存为 0、库存不足）：在子体层识别、命中对象记录到具体子 ASIN，按命中子体的变体重要性取列（主要色 / 次要色 / 长尾色）。

- 异常属于链接级还是变体级，见模块 2.0 归类清单；实际命中对象与默认归类不一致时，以模块 2.0 的通用规则为准（合规异常固定子体级，不适用兜底）。

- 次要色、长尾色基础分已按配置表预设，Agent 直接读取表内数值，不再二次计算。

### 4.2 产品定位系数

| 产品定位 | 定位系数 |
| --- | --- |
| T0 战略级 | 1.5 |
| T1 重点 | 1.2 |
| T2 常规 | 1.0 |
| T3 长尾 | 0.6 |

定位系数间距决定”严重度要差多少才能反超一个定位档”。当前默认下，一个严重度档（S1→S0）足以反超一个定位档；间距越大越难反超。若需收紧两档反超，可拉大 T0/T1/T2 间距。

### 4.5 多异常并发权重

| 参数 | 默认值 | 可选配置 |
| --- | --- | --- |
| 并发权重 | 0.2 | 按严重度分级：其余异常中 S0/S1 取 0.3、S2 取 0.15 |

产品执行分数 = 最高单异常执行分数 + 其余各异常执行分数 × 并发权重。并发只通过分数体现，不设硬性置顶；“必须人工介入”为独立属性，不改变排序。

并发加成只计算正式异常。数据不足、样本不足观察、观察类提示、被共因去重后不作为主任务输出的异常，以及被共现去重后仅作为关联现象展示的异常，不参与并发加成。

### 4.6 执行优先级阈值

| 执行优先级 | 执行分数区间 | 处理要求 |
| --- | --- | --- |
| 执行 P0 | ≥ 90 | 当天处理 |
| 执行 P1 | 45 – 89 | 3 天内处理 |
| 执行 P2 | < 45 | 7 天内处理 |

阈值建议按”当天人力可消化条数”反推 P0 阈值后校准。P2 为 7 天内处理（时限最宽），运营可在期内先观察再决定处理或升降级，详见模块 5。

P2 的”7 天内处理”指 7 天内完成初次处理或给出处理判断；若 P2 满 14 天仍未处理，则按模块 5 升级为 P1。

### 4.8 完整算例（串联模块 1–4）

某 T1 重点产品、收割期、旺季前期，同时存在两个异常：

- 异常 A：黑色/M 码 FBA 可售库存为 0（变体级·库存类，命中主要色）→ 严重度 S0，基础分取 S0×主要色 = 100。

- 异常 B：灰色/XL 图片异常（变体级，长尾色）→ 严重度 S1，基础分取 S1×长尾色 = 15。

公共系数：定位 1.2 × 阶段 1.3 × 淡旺季 1.2 = 1.872。

单异常执行分数：

- A = 100 × 1.872 = 187.2

- B = 15 × 1.872 = 28.08

产品执行分数（最高分主导 + 其余 × 0.2 并发权重）：

187.2 + 28.08 × 0.2 = 187.2 + 5.62 = 192.82

192.82 ≥ 90 → 执行优先级 P0（当天处理）。

说明：主要色断货（A）主导了整张卡的执行分数与排序——黑色/M 为主要色，取 S0×主要色 = 100；长尾色图片异常（B）因变体重要性低、基础分仅 15，对结果影响很小但仍记录在卡内。任务卡归集到该父 ASIN，卡内列 A、B 两条子体明细 + 各自变体重要性 + 各自严重度；父卡严重度取子体最高 = S0。

本算例默认异常已通过模块 3 判定为正式 S0 / S1 异常；数据不足、样本不足观察、观察类提示不进入本算例打分。

### 4.9 分数相同时的破平规则（异常类型次序）

产品呈现顺序的第一排序键是产品执行分数（分数高的在前）。当两个产品的产品执行分数完全相同，或因系统展示/排序精度限制被视为相同分数时，用异常类型次序作为第二排序键破平：异常类型次序号小的（靠前的）先呈现。规则不改分数、不加分、不改变 P0/P1/P2 优先级，仅决定同分时谁先呈现。一个产品有多个异常时，取其最靠前（次序号最小）的异常参与破平。分数存在可区分差异时，仍按产品执行分数排序，本规则不介入。

破平规则只作用于已进入正式打分的主任务异常；数据不足、样本不足观察、观察类提示、关联现象、被共因去重后不作为主任务输出的异常，不参与破平。

触发边界：本规则仅在产品执行分数完全相同，或分数差小于系统展示/排序精度时启用。例如系统仅展示整数分时，92.1 与 92.4 可视为同分；若系统保留两位小数，则只有完全相同或差值低于 0.01 的情况才视为同分。具体精度由实现侧配置，但不得扩大到正常分数差异。

禁止项：破平规则不得提前参与异常基础分、单异常执行分数、产品执行分数或 P0/P1/P2 阈值映射；不得因为异常类型次序靠前而加分、升档或覆盖产品执行分数排序。

示例：产品 A、B 分数都是 92。A 的异常类型为次序 1（完全不能卖），B 为次序 3（合规高风险）→ A 次序号更小 → A 先呈现。

本表为同分破平排序表，不改变异常大类归属。评分异常仍归属模块 2.7 售后异常，但因评分下降对买家信任和转化影响更直接，破平次序上高于近期集中差评和退款异常。

异常类型次序表：

| 次序 | 异常类型 | 包含点位 |
| --- | --- | --- |
| 1 | 完全不能卖 | 链接不可售、库存不可售、FBA 可售库存为 0 |
| 2 | 卖得受阻 / 高断货风险 | Buy Box 丢失、变体掉线、父子体关系异常、库存不足 |
| 3 | 合规高风险 | 合规异常 |
| 4 | 已发生实际损失 | 滞销异常 |
| 5 | 交易表现 / 信任损失 | 销量异常（下降）、链接转化率异常下降、ACOS 异常、广告花费异常、目标偏离、自然流量异常、卡位异常、评分异常 |
| 6 | 库存积压 | 库存积压 |
| 7 | 内容 | 主图异常、标题异常、五点异常、图片异常、A+ 异常 |
| 8 | 价格 | 促销异常、变体价差异常 |
