# 模块 5　升降级与解除规则



打分（模块 4）决定异常的初始执行优先级（P0/P1/P2）。本模块定义初始优先级之后的事后调整——什么情况升档、降档、解除。升降级与打分分工：异常多/严重靠打分自然体现，超期/人工干预靠本模块规则。

本模块只作用于已经生成正式 P0 / P1 / P2 的异常任务；数据不足、样本不足观察、转化率样本不足观察、新品库存压力待观察、放量机会待评估等观察类结果，不进入升降级与解除流程。

## 5.0 总则

1. 升级：在打分结果之上，因打分覆盖不到的因素（超期、人工高风险）强制升档。

2. 降级：仅允许人工直接降级，且必须填写原因。

3. 解除：异常关闭、移出处理队列（人工确认或自动恢复）。

4. 恶化不单列规则：数据恶化导致更严重，是打分的默认行为（数据变重 → 分数升 → 自然到更高档），不需要单独的升级规则。波及面达到模块 3.3 共因上调条件（3 个及以上表现型异常共因），属于“数据恶化导致更严重”的一种具体体现，同属本条默认行为范畴，不属于模块 5.1 的硬跳档升级，不需要人工标记或额外审批。

5. 并发不单列规则：同链接多异常已由打分体现（异常越多产品执行分数越高，自然升档），不设硬跳档。

## 5.1 升级规则（硬跳档）

| 当前等级 | 升级条件 | 升级后 | 要求 |

| --- | --- | --- | --- |

| P1 | 满 7 天未处理 | P0 | 硬跳档 |

| P2 | 满 14 天未处理 | P1 | 硬跳档 |

| 任意等级 | 运营人工标记高风险 | 仅允许升档至 P0 / P1 | 必须填写高风险原因 |



超期升级是硬跳档（满时间必定升档），不靠加分——保证“拖太久必定升级”的确定性。超期时长按执行优先级计（P1 的 7 天、P2 的 14 天）。

超期升级只判断是否“未处理”，不判断是否“未关闭”。若运营已完成初次处理或给出处理判断，但异常尚待复查 / 尚未关闭，不因“未关闭”触发超期升级。

运营人工标记高风险时，只允许升档至 P0 / P1，并必须填写高风险原因；不得通过“标记高风险”进行降级，降级统一走 5.2。

## 5.2 降级规则

| 降级方式 | 条件 | 要求 |

| --- | --- | --- |

| 人工直接降级 | 运营判断当前等级偏高（如已知可接受、有意为之、误判等） | 必填降级原因，记入处理记录 |



降级分两种方式：人工直接降级，和系统自动降级（仅限模块 3.3 共因上调回落场景）。人工直接降级须写明原因，便于追溯。系统自动降级仅适用于以下情形：该异常此前经模块 3.3 共因上调规则提升过严重度，且本轮复扫共因数量降至规则阈值（3 个）以下——此时系统自动将严重度回落至初判档位，无需人工填写原因，但须记录变更前后档位与触发 / 回落依据。除此共因回落场景外，其余任何异常一律不适用系统自动降级，仍须人工直接降级。人工降级优先：若该异常此前已被运营人工直接降级，共因回落不直接覆盖人工判断，当前展示等级仍维持人工降级结果；系统仅在任务卡中提示“该异常共因已回落，当前维持人工降级，建议复核”，由运营决定是否撤销降级。

降级只改变当前执行优先级，不关闭异常；异常是否关闭仍按 5.3 解除规则执行。人工降级后，若后续复扫发现异常仍然严重，但系统识别到该产品该异常已被人工降级，则继续按人工降级后的等级执行，不立即覆盖人工判断。若连续超过 7 次复扫仍发现该异常保持严重状态，系统可按最新数据重新计算执行优先级，并提示运营复核是否继续维持人工降级。

## 5.3 解除规则（异常关闭）

| 解除方式 | 条件 | 要求 |

| --- | --- | --- |

| 人工确认已处理并关闭 | 运营确认已完成处理，且无需继续跟进 | 填处理动作 |

| 人工确认误报 | 核实为误报 | 填误报原因，记入误报样本（供校准） |

| 人工确认不需处理 | 运营判断无需处理 | 必填原因 |

| 自动恢复关闭 | Agent 复扫或下一判定周期发现问题已不存在 | 按异常类型执行自动恢复关闭规则，系统自动关闭并留记录备查 |



解除即异常关闭、移出队列。前三种为人工确认，第四种为系统自动（问题不存在了即自动关闭，但需按下表区分异常类型）。

| 异常类型 | 自动恢复关闭规则 |

| --- | --- |

| 现象即原因型异常 | 复扫发现问题已不存在，可自动关闭并留记录。 |

| 日维度 / 连续窗口表现型异常 | 对 ACOS、广告花费、销量、目标偏离、自然流量、卡位等连续窗口类异常，需连续 3 天不再满足异常条件后，才自动恢复关闭。 |

| 周维度异常 | 链接转化率异常、退款异常等周维度异常本身一周巡检一次，以下一次周维度巡检结果为准；下一次巡检不再满足异常条件，才可自动恢复关闭。 |

| 评分异常 | 评分回升至不再满足评分异常条件后，才可自动恢复关闭。 |



## 5.4 与打分、记忆的边界

1. 升降级作用于已打分的异常，是打分之后的事后调整，不改打分公式本身。

2. 升降级与解除规则不改变异常严重度 S，也不改变模块 4 的原始执行分数；它只改变任务当前展示等级或当前状态。

3. 人工降级/解除改变的是该异常的当前状态，不影响其它异常的打分。

4. 等级变更的历史追踪与变更提示（如“这条从 P2 变成了 P1，要提示运营”）依赖记忆系统（跨时间对比状态），属状态跟踪范畴，归方案文档/记忆系统处理，不在本知识库。

5. 例外：共因回落（模块 3.3 共因上调规则触发的系统自动降级）不适用本条第 2 款“不改变异常严重度 S、不改变模块 4 原始执行分数”的限制——回落时严重度 S、模块 4.1 基础分与产品执行分数均按回落后的新档位重新计算。此为唯一例外，因共因回落本质是严重度的重判，仅在执行方式上归入模块 5.2 的系统自动降级流程管理；其余任何升降级仍严格遵守第 2 款，不改变严重度与原始分数。
