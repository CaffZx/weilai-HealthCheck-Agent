## 7. 未投递但不属于数据缺失

58 个经营单元没有发送给中控，是因为巡检没有发现真实异常，而不是因为核心数据缺失。

中控 v2 合同要求 `proposal.anomalies` 至少包含一条真实异常。系统禁止伪造异常，因此这些正常经营单元只保留在 MySQL 巡检记录和覆盖报告中，不向中控提交异常建议。

## 8. 最终结论

1. 父级产品、销售、利润、广告汇总和库存核心事实总体完整，199 个成功经营单元的核心 MCP 均已通过补跑恢复。
2. 当前主要短板是子体深度事实、负责人、经营模式、逐日流量、净现金回收和剩余主图。
3. MCP 超时不是最终主要缺口；超时工具经过补跑已经恢复。
4. 一批数据已经获取但没有进入中控顶层结构，需要根据中控合同决定增加字段、增加事实快照类型或保持仅供巡检内部使用。
5. 中控正式接收 140 个唯一异常经营单元，全部成功，无失败回执。
