# 巡检 Agent v2.0 — 进程与巡检启动运维规范

> 生效日期:2026-08-12
> 目标:一切进程走 systemd,禁止 nohup / SSH 手拉,保证"永不挤压、永不孤儿、SSH 断开无影响"。

## 一、当前托管的 systemd 服务清单

| 服务 | 角色 | 端口/说明 | 副本数 |
|---|---|---|---|
| `weilai-v2-api.service` | FastAPI 主 API | `:8020` | 1 |
| `weilai-v2-review.service` | Review MCP | `:8791` (127.0.0.1) | 1 |
| `weilai-v2-delivery@{1..6}.service` | 中控 Outbox 投递 worker | 通过 `FOR UPDATE SKIP LOCKED` 并行抢锁 | 6 |
| `weilai-v2-patrol-batch.service` | 巡检批量采集 | 一次性任务,`Restart=no` | 1 |

失败自动检查:`systemctl list-units "weilai-*" --state=failed` 应始终为 0。

## 二、启动巡检的唯一方式

### 常规启动(生产)

```bash
# 起一轮全量巡检(all-active, concurrency=10)
systemctl start weilai-v2-patrol-batch.service

# 查看是否已经在跑(重复 start 不会挤压,systemd 会拒绝再起)
systemctl is-active weilai-v2-patrol-batch.service

# 看进度
tail -f /opt/weilai-HealthCheck-Agent-v2.0/logs/patrol-batch.log

# 查健康
curl -s http://127.0.0.1:8020/api/v1/patrol/health | python3 -m json.tool

# 优雅停止(会等最多 60 秒让 in-flight 落库)
systemctl stop weilai-v2-patrol-batch.service
```

### 禁止的做法

- `nohup python -m scripts.run_real_patrol_batch ... &`  — SSH 断了会带走,SSH 里连续跑两次会挤压
- `tmux/screen` 里跑长任务 — 无监督重启、无日志归档
- 在多台 SSH 里各起一份 — 会引发数据库锁竞争

### 若要改参数

编辑 `/etc/systemd/system/weilai-v2-patrol-batch.service` 的 `ExecStart`,然后:

```bash
systemctl daemon-reload
systemctl restart weilai-v2-patrol-batch.service
```

支持参数(见 `scripts/run_real_patrol_batch.py`):
- `--all-active`:巡检全部启用中的经营单元
- `--concurrency N`:并发,当前上限 32(默认 4,当前用 10)
- `--start-offset N`:断点续跑

## 三、投递 worker(6 实例)

### 为什么是 6 个

代码 `integrations/control_center_delivery.py` 中,每个 worker 单次 `SELECT ... LIMIT 1 FOR UPDATE SKIP LOCKED` 只抢 1 条,处理超时 60s。单进程最坏 1 分钟出 1 条,与外部中控 MCP 网络往返延迟成线性。

采集侧 `concurrency=10` 产入,投递 6 实例基本能顶住,不出现 outbox 长期堆积。

### 常用命令

```bash
# 全部启停
systemctl start weilai-v2-delivery@{1..6}.service
systemctl stop  weilai-v2-delivery@{1..6}.service

# 单实例操作
systemctl restart weilai-v2-delivery@3.service

# 每个实例独立日志
tail -f /opt/weilai-HealthCheck-Agent-v2.0/logs/delivery-worker-1.log

# 想扩容(比如 10 个)
systemctl enable --now weilai-v2-delivery@{7,8,9,10}.service
```

```

## 七、日常巡检的推荐 SOP

1. 起巡检:`systemctl start weilai-v2-patrol-batch.service`
2. 看状态:`systemctl status weilai-v2-patrol-batch.service --no-pager -n 5`
3. 看健康:`curl -s http://127.0.0.1:8020/api/v1/patrol/health | python3 -m json.tool`
4. 看 outbox 消化:`curl -s http://127.0.0.1:8020/api/v1/patrol/metrics | grep outbox_total`
5. 全景进程一览:`systemctl list-units "weilai-v2-*" --no-pager`
6. 告警检查:health 里的 `alerts` 字段应逐步为空

   /opt/weilai-HealthCheck-Agent-v2.0/config/settings.yaml

# 恢复脚本
cp /opt/weilai-HealthCheck-Agent-v2.0/scripts/run_real_patrol_batch.py.bak-conc10 \
   /opt/weilai-HealthCheck-Agent-v2.0/scripts/run_real_patrol_batch.py

# 恢复被删的 systemd unit(如需)
cp /root/systemd-backup-20260812/*.service /etc/systemd/system/

# 收敛 delivery 回 1 实例
systemctl disable --now weilai-v2-delivery@{1..6}.service
systemctl enable --now weilai-v2-delivery.service
```
