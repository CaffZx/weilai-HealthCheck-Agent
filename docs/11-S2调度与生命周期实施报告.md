# S2 调度与生命周期实施报告

> 日期：2026-07-31  
> 状态：S2 退出条件通过  
> 实施基线：`docs/07-巡检AgentV2最终改造实施方案.md`

## 交付结果

- 新增 MySQL 批次与任务队列，支持每日、到期和人工触发；
- 每日批次使用业务日、范围哈希和规则版本生成确定性幂等键；
- 同经营单元跨批次创建使用 MySQL 命名锁，避免并发活动任务；
- Worker 使用 `FOR UPDATE SKIP LOCKED` 领取任务；
- 实现指数退避、最大重试 `DEAD`、崩溃任务回收和真实批次聚合；
- 实现 Scheduler 数据库租约、续租、过期接管和持有者释放；
- 实现 `02:00`/`07:00` 共用每日幂等入口及 15 分钟到期复扫入口；
- 提供 `scripts/run_daily.sh` 与 `scripts/run_daily_fallback.sh` 两个显式部署命令；
- 一个业务批次中的 Job 默认每 50 条批量插入，拆分数据库写入但不拆分业务 Batch；
- 到期复扫只调度 MCP 有效清单中、确实到期且没有活动 Job 的经营单元；
- 实现信号首次、持续、完整事实两次未命中恢复、复发及数据缺口对账；
- 每次对账使用乐观版本锁并保存不可变 occurrence；
- 新增完整信号 payload 持久化，确保生命周期更新后仍可重建对外合同；
- 测试库升级到 Alembic revision `0002_signal_payload`，表数量保持 11 张。

## 验证结果

| 场景 | 结果 |
|---|---|
| 两个 Scheduler 同时创建每日批次 | 只创建一个，另一个返回原批次 |
| 两个 Worker 并发领取 | 不重复领取，剩余任务后续轮询可取 |
| 可重试失败 | 按退避时间回到 `PENDING` |
| 达到最大重试 | 进入 `DEAD`，批次计入失败 |
| Worker 崩溃 | 过期 `RUNNING` 任务可回收 |
| 一成一败批次 | 聚合为 `PARTIAL_SUCCESS` |
| Scheduler 租约 | 未过期不可抢占，过期后可接管 |
| 首次和持续命中 | 产生 `DETECTED`，不重复建活动信号 |
| 连续完整未命中 | 第一次 `MISSED`，第二次 `RECOVERED` |
| 数据缺失 | 产生 `DATA_GAP`，未命中次数不增加 |
| 已恢复再次命中 | `RECURRED`，复发次数加一 |
| 生命周期版本 | 测试序列从 1 递增到 4 |
| 测试数据清理 | 全部回滚或删除，业务表保持空 |

## 运行边界

`feature_flags.scheduler_enabled` 当前仍为 `false`。S4 已完成 #30 Provider 与事实 Adapter，
但 #30 不返回父级身份；#9 备用 Provider 已实现，却尚无非 SQLite 的权威负责人/店铺/站点映射。Scheduler
不能用本地旧表或默认站点伪造有效单元，需先冻结运行枚举策略再开启自动调度。

旧 `integrations/task_queue.py` 和旧 SQLite Scheduler 暂时保留，仅供历史链路兼容；
S3 已把正式 `integrations.worker` 命令切换到 MySQL 纯巡检 Worker，不在 S2 物理删除旧模块。
