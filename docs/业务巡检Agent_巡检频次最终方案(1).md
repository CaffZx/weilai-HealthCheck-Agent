# 业务巡检 Agent 巡检频次最终方案

## 1. 核心思路

本系统不做“每日全量扫描所有 ASIN、所有异常”。

采用：

> 首轮基础建档 → 每日数据监控 → 异常/变更触发定向巡检 → 命中异常后按事件复查 → 低频心跳兜底 → 必要时人工触发深度体检

也就是：

- 数据类指标每日计算；
- 状态类、内容类、库存类按变化或到期巡检；
- 发现异常后才做定向深查；
- 初筛尽量全部用代码；
- 能用字段、阈值、标签、配置判断的，不进大模型；
- 只有代码无法判断的语义、文本、复杂原因才交给 Agent；
- ERP 里保留“跑深度体检”按钮，允许人工主动触发。

## 2. 设计边界

本方案只定义：

- 什么时候巡检；
- 巡检谁；
- 巡检哪些模块；
- 命中异常后多久复查；
- 什么时候触发深度体检；
- 广告相关如何给出“要不要跑 / 是否需要进一步检查”的建议。

本方案不重新定义：

- S0/S1/S2 严重度；
- P0/P1/P2 打分规则；
- 异常识别阈值；
- 处理建议库；
- 广告自动执行动作。

系统边界：

| 内容 | 负责方 | 说明 |
| --- | --- | --- |
| 低成本初筛 | 代码 | 尽量通过字段、标签、阈值完成 |
| 打分排序 | 代码 | P0/P1/P2 由确定性控制核计算 |
| 深度体检 | Agent / 代码组合 | 由控制核触发或人工按钮触发 |
| 广告是否建议关注 | 巡检 Agent 初筛 | 判断广告设置、阶段、数据是否匹配 |
| 广告具体怎么调 | 广告决策 Agent / 广告系统 | 不在巡检 Agent 内直接执行 |
| 最终业务动作 | 运营人工 / ERP 审核流 | 系统只建议，不直接改业务 |

## 3. 首轮建档

系统上线后，先对所有父 ASIN / 子 ASIN 做一次基础建档。

首轮只抓低成本结构化字段，不做大模型深度判断。

| 模块 | 首轮是否做 | 说明 |
| --- | --- | --- |
| 父子 ASIN 关系 | 做 | 建立父体、子体、颜色、尺码关系 |
| 产品标签 | 做 | T0/T1/T2/T3、阶段、淡旺季、变体重要性 |
| 链接状态 | 做 | 是否在售、是否可售、是否抑制、是否禁止显示 |
| 库存可售 | 做 | FBA 可售、库存不足、库存不可售 |
| 价格促销 | 做 | 到手价、Coupon、促销活动 |
| 内容结构 | 做 | 主图是否存在、副图数量、标题长度、五点数量、A+ 是否存在 |
| 经营数据 | 做 | 销量、CVR、ACOS、广告花费、自然流量、评分、退款 |
| 广告设置 | 做 | 当前保存的广告目的、预算目标、目标 ACOS、投放状态等标签/配置 |
| 图片视觉质量 | 不做 | 当前 DeepSeek 不具备视觉能力 |
| 大模型原因分析 | 不默认做 | 只对重点异常触发 |

首轮完成后，为每个对象生成：

- `last_inspected_at`
- `next_inspection_time`
- `health_status`
- `open_event_list`
- `trigger_reason`

## 4. 每日数据监控

销量、CVR、ACOS、广告花费、评分、退款等表现数据，应该每日从 ERP / 数仓计算。

但这里要区分：

| 动作 | 是否每日做 | 说明 |
| --- | --- | --- |
| 表现数据监控 | 每日做 | 每天计算销量、CVR、ACOS、广告花费、评分等 |
| 广告设置匹配初筛 | 每日做 | 用代码判断广告设置、阶段、广告数据是否匹配 |
| 深度巡检 / 原因查证 | 异常时才做 | 只有达到异常阈值、初筛不匹配，或人工点击按钮时才触发 |

举例：

- 如果销量正常，只记录数据。
- 如果销量连续 3 天下滑，则触发定向巡检，查库存、链接、Buy Box、价格、促销、广告、内容、售后等原因。
- 如果当前保存的广告目的是“推进/放量”，但广告花费长期花不出去、曝光不足，则触发广告相关体检建议。
- 如果当前保存的广告目的是“盈利/收割”，但 ACOS 连续超出目标，则触发广告相关体检建议。

## 5. 巡检触发入口

后续巡检由 5 类触发组成。

| 触发类型 | 触发条件 | 说明 |
| --- | --- | --- |
| 变更触发 | 库存变、价格变、促销变、内容更新时间变、链接状态变 | 有变化才查对应模块 |
| 表现触发 | 销量下降、CVR 下降、ACOS 升高、广告花费异常、评分下降 | 每日监控，异常后触发查因 |
| 广告匹配触发 | 当前广告设置、商品阶段、广告数据不匹配 | 用代码初筛是否需要广告体检 |
| 高风险触发 | T0/T1、主要色、S0、P0/P1 未关闭 | 高价值、高风险对象加密巡检 |
| 人工触发 | ERP 点击“跑深度体检”按钮 | 人工主动触发深度检查 |
| 心跳兜底 | 长时间未巡检 | 防止一直没问题就永远不扫 |

`next_inspection_time` 是兜底机制，不是唯一触发条件。

## 6. 健康商品基础巡检频次

健康商品指当前没有正式异常事件的 ASIN。

| 商品类型 | 基础巡检频次 |
| --- | --- |
| T0/T1 主要色 | 每日 |
| T0/T1 次要色 | 3 天一次 |
| T0/T1 长尾色 | 7 天一次 |
| T2 主要色 | 3 天一次 |
| T2 次要色 | 7 天一次 |
| T2 长尾色 | 14 天一次 |
| T3 主要色 | 7 天一次 |
| T3 次要色 | 14 天一次 |
| T3 长尾色 | 30 天一次 |
| 清货商品主要色 | 14 天一次 |
| 清货商品次要色 / 长尾色 | 30 天一次 |

这只是基础频次。如果出现数据异常、状态变化、广告设置不匹配或人工触发，立即进入定向巡检。

## 7. 各模块巡检策略

| 模块 | 是否每日全量扫 | 推荐策略 |
| --- | --- | --- |
| 链接状态 | 不全量 | 高价值每日；其他按状态变化 + 心跳 |
| 库存可售 | 核心款高频 | 主要色、高价值款每日；长尾低频 |
| 价格促销 | 不全量 | 价格/活动变化时查；活动期加密 |
| 内容完整性 | 不全量 | 内容更新时间变化、审核状态异常、CVR 下跌时查 |
| 主图异常 | 不做视觉全扫 | 只查主图缺失、禁止显示、审核异常字段 |
| 销量/CVR | 每日聚合 | 每日算，异常后查因 |
| ACOS/广告花费 | 每日聚合 | 每日算，异常后查因 |
| 广告设置匹配 | 每日初筛 | 判断当前保存设置、阶段、广告数据是否匹配 |
| 售后评分/退款 | 每日或每周 | 新差评、评分下降、退款异常时触发 |
| 合规属性 | 不全量 | 平台状态变化、风险提示时查，高风险兜底 |

## 8. 深度巡检规则

深度巡检不是大模型自由发挥，而是控制核分派后的定向检查。

第一层低成本巡检命中异常后，才进入深度巡检。

| 第一层发现 | 深度巡检内容 |
| --- | --- |
| 销量下降 | 查库存、链接状态、Buy Box、价格、促销、广告、内容、售后 |
| CVR 下降 | 查主图状态、标题、五点、价格、促销、差评 |
| ACOS 升高 | 查广告目标、当前广告设置、转化、价格、库存、内容承接 |
| 链接不可售 | 查库存、合规、配送、平台限制、价格问题 |
| 库存异常 | 查是否主要色、是否影响广告、是否需要提示广告控制放量 |
| 合规异常 | 查平台提示、类目、属性、是否必须人工介入 |
| 售后异常 | 查差评原因、评分趋势、是否影响销量/CVR |
| 广告设置不匹配 | 查当前广告目的、预算目标、目标 ACOS 与阶段和数据是否匹配 |
| 人工点击深度体检 | 按人工选择范围执行深度检查 |

深度巡检优先代码规则。

只有以下情况才交给 Agent：

- 差评文本归因；
- 标题/五点语义判断；
- 复杂根因诊断；
- 需要归纳解释的任务卡内容；
- 广告决策 Agent 需要做具体广告优化建议时。

Agent 只输出 findings、解释或建议，不参与巡检主链路的打分、排序和写回审批。

## 9. 异常事件复查频次

命中正式异常后，进入事件池，按异常类型复查。

| 异常类型 | 默认复查频次 | 加急规则 |
| --- | --- | --- |
| Listing 不在售 / 链接不可售 | 1 天 | 无 |
| Buy Box 丢失 | 3 天 | 主要色 1 天 |
| 父子体关系异常 | 1 天 | 无 |
| 主图缺失 / 禁止显示 / 审核异常 | 3 天 | 主要色 1 天 |
| 标题异常 | 3 天 | T0/T1 1 天 |
| 五点异常 | 7 天 | T0/T1 3 天 |
| A+ 异常 | 14 天 | T0/T1 7 天 |
| 库存不可售 | 3 天 | 主要色 1 天 |
| FBA 可售为 0 | 7 天 | 主要色 3 天；运营预计到货时间优先 |
| 库存不足 | 7 天 | 主要色 3 天；运营预计到货时间优先 |
| 促销异常 | 1 天 | 无 |
| 价格异常 | 7 天 | 主要色 1 天 |
| 合规异常 | 3 天 | S0 合规 1 天，必须人工介入 |
| 销量异常 | 3 天 | 无 |
| ACOS 异常 | 3 天 | 无 |
| 广告花费异常 | 3 天 | 无 |
| 广告设置不匹配 | 3 天 | 人工已触发广告体检后，按广告体检结果复查 |
| 目标偏离 | 3 天 | 无 |
| 自然流量 / 卡位异常 | 3 天 | 无 |
| 差评 / 评分异常 | 7 天 | T0/T1 3 天 |
| 退款异常 | 14 天 | T0/T1 7 天 |
| 库存积压 / 滞销 | 30 天 | 无 |

运营填写预计恢复时间时，优先使用运营时间。

## 10. 主图判断边界

第一版不做视觉识别。

主图异常只判断：

- 主图是否缺失；
- 是否被平台禁止显示；
- 图片审核状态是否异常；
- 前台是否展示异常；
- 后台是否有图片违规提示。

不判断：

- 是否模糊；
- 是否白底；
- 是否美观；
- 构图是否合理。

这些等后续接入多模态模型再做。

## 11. 广告建议规则

广告建议不是单纯由商品健康度触发，而是由以下四类信息共同判断：

> 商品健康状态 + 当前商品阶段 + 当前保存的广告设置 + 当前广告数据表现

其中“当前保存的广告设置”包括但不限于：

- 广告目的；
- 预算目标；
- 目标 ACOS；
- 当前 Campaign / 关键词策略；
- 当前是否处于放量、控 ACOS、清货、测试等策略。

巡检 Agent 只做广告代码初筛，不直接替代广告决策 Agent。

### 11.1 广告初筛判断

| 判断项 | 代码初筛逻辑 | 输出 |
| --- | --- | --- |
| 商品是否适合继续跑广告 | 链接、库存、Buy Box、合规是否正常 | 继续跑 / 控制放量 / 暂停或降低 |
| 阶段与广告目的是否匹配 | 商品阶段与保存的广告目的是否一致 | 匹配 / 不匹配 |
| 目标 ACOS 与实际 ACOS 是否匹配 | 实际 ACOS 是否连续超出目标或近 7 天均值 | 正常 / 需关注 |
| 预算目标与实际花费是否匹配 | 是否花不出去或异常超支 | 正常 / 需关注 |
| 销量变化与广告动作是否匹配 | 销量增长是否未放量，销量下降是否广告仍高耗 | 正常 / 需关注 |

### 11.2 广告建议输出

| 触发情况 | 广告建议 |
| --- | --- |
| 链接不可售 | 建议暂停或降低广告，避免浪费 |
| FBA 可售为 0 | 建议暂停或降低该变体广告 |
| 库存不足 | 建议控制放量 |
| 销量下降 | 建议检查当前广告设置与转化承接是否匹配 |
| ACOS 升高 | 建议检查目标 ACOS、关键词、出价、预算与当前阶段是否匹配 |
| 销量增长但未放量 | 建议评估广告设置是否应切换为放量/推进 |
| 当前广告目的与商品阶段不匹配 | 建议触发广告体检，重新评估广告目的 |
| 当前预算目标与实际花费不匹配 | 建议触发广告体检，检查预算与投放结构 |

### 11.3 广告字段输出

ERP 任务卡建议展示：

| 字段 | 说明 |
| --- | --- |
| 是否建议继续跑广告 | 继续跑 / 控制放量 / 暂停或降低 / 数据不足 |
| 广告设置是否匹配 | 匹配 / 不匹配 / 无法判断 |
| 是否建议广告体检 | 是 / 否 |
| 触发原因 | 为什么建议或不建议 |
| 关联异常 | 库存、链接、销量、ACOS 等 |
| 广告体检入口 | 点击后进入广告决策 Agent 或触发深度体检 |

系统不自动改广告。

## 12. ERP 人工触发深度体检按钮

ERP / 在线系统需要提供一个按钮：

> 跑深度体检

这个按钮是整个项目通用能力，不只针对广告。

用途：

- 运营觉得某个商品“看起来不对”，但系统未自动触发时，可以人工触发；
- 老板或运营抽查重点商品时，可以强制跑一次；
- 系统自动初筛结果为“数据不足 / 无法判断”时，人工可补充原因后触发；
- 广告、库存、链接、内容、售后等模块都可以按范围触发。

建议按钮选项：

| 选项 | 说明 |
| --- | --- |
| 商品健康体检 | 查链接、库存、价格、内容、合规 |
| 广告体检 | 查广告设置、广告表现、阶段匹配 |
| 售后体检 | 查差评、评分、退款原因 |
| 全量体检 | 对该父 ASIN 做一次完整深度检查 |
| 指定模块体检 | 运营选择一个或多个模块 |

建议记录字段：

| 字段 | 说明 |
| --- | --- |
| manual_deep_check | 是否人工触发 |
| manual_trigger_user | 触发人 |
| manual_trigger_time | 触发时间 |
| manual_trigger_reason | 触发原因 |
| deep_check_scope | 体检范围 |

人工触发不等于绕过风控。

深度体检仍需：

- 检查数据是否完整；
- 扣减预算；
- 走只读取数；
- 不自动执行广告或业务动作。

## 13. 表现型异常跳过规则

当链接或核心变体已经不能正常展示/成交时，表现数据会失真，此时不再重复判断表现型异常。

| 场景 | 是否跳过表现型异常 |
| --- | --- |
| 整条链接不可售 | 跳过 |
| 父体被拆 | 跳过 |
| 主要色 FBA 为 0 | 跳过 |
| 主要色 Buy Box 丢失 | 跳过 |
| 次要色 / 长尾色异常 | 不默认跳过 |
| 内容轻微异常 | 不跳过 |

恢复后，从下一轮开始恢复表现型巡检。

## 14. 扫描优先级

如果当天扫描量有限，优先扫：

1. 人工触发深度体检；
2. P0 未关闭；
3. S0 异常；
4. T0/T1 商品；
5. 主要色；
6. 链接不可售、库存、Buy Box、合规；
7. 已到复查时间的异常事件；
8. 新触发的表现异常；
9. 广告设置不匹配；
10. 健康商品心跳兜底。

健康低风险商品可以延后，但不能无限期不扫。

## 15. 最终落地口径

第一版研发只需要做到：

1. 首轮低成本建档；
2. 每日计算表现数据；
3. 每日用代码初筛广告设置、商品阶段、广告数据是否匹配；
4. 用变更和异常触发定向巡检；
5. 健康商品按低频心跳兜底；
6. 异常商品按事件复查；
7. 主图不做视觉判断；
8. 广告只判断是否建议继续跑、是否建议体检，不自动执行；
9. ERP 提供“跑深度体检”按钮；
10. Agent 只处理代码判断不了的语义、文本和复杂原因。

## 16. 最终一句话

本方案不是“每日全量扫描系统”，而是：

> 低成本数据每日监控，异常信号触发定向巡检；广告部分用代码判断当前广告设置、商品阶段和广告数据是否匹配；高价值和高风险商品加密，健康长尾商品低频兜底；代码能判断的代码判断，Agent 只处理模糊和复杂判断，人工可在 ERP 一键触发深度体检。
