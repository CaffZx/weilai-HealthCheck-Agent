## 关于第 16 条的说明

本文最初记录的跨单元调度缺口已在 V2 S2/S4 增量中补齐。当前实现如下：

**已做到**
- 任务持久化在 MySQL，进程重启不丢；
- `claim()` 使用 `FOR UPDATE SKIP LOCKED`，多 Worker 不会重复处理同一条；
- 失败按 30s → 60s → 120s 指数退避，超次数进 `FAILED`/`DEAD`；
- `reclaim_stale()` 回收进程崩溃留下的 RUNNING 任务；
- MCP 分页清单驱动每日和到期 Scheduler；`02:00` 主调度与 `07:00` 兜底复用同一幂等键；
- 一个业务 Batch 内按默认 50 条批量插入 Job，不拆成多个业务批次；
- MCP 并发有信号量上限，不会把上游打挂。

仍未完成的是**运行枚举合同冻结和真实规模压测**：#30 全量清单没有父 ASIN/父 Seller SKU；
#9 有父级字段但尚无非 SQLite 权威负责人名册。因此 Provider 会拒绝不完整身份，灰度阶段继续保持 `INTERNAL_ONLY`。10,000 单元的吞吐、
上游限流参数和 Worker 副本数需在正式 MCP 环境按压测结果确定。

## 交接包不变量对照（10 条）

方案 §29 之外，交接包《核心对象与字段契约 v0.4》§8 有十条不可违反的不变量。
巡检 Agent 涉及的部分：

| # | 不变量 | 巡检 Agent 的落地 |
|---|---|---|
| 1 | 一个经营单元只有一个当前父级模式 | 巡检不产生模式，只消费经营模式 Agent 的唯一结论 |
| 2 | 子 ASIN 处置不创建父级模式 | `AnomalySignal.child_asins` 只表达例外范围，不带模式字段 |
| 3 | 父级停止补货必然清货或退出 | `ModeDecisionResult` 校验器强制（`test_stop_replenishment_requires_exit_or_clearance`） |
| 4 | 最佳可行净现金回收为负必然立即退出 | 检测到负值时打 `NEGATIVE_CASH_RECOVERY` 约束标记，排序最高优先 |
| 5 | 专业 Agent 不拥有模式决定权 | 巡检不修改 `recommended_mode`；广告建议与模式冲突时拦截而非覆写 |
| 6 | 没有批准计划不得执行增加承诺的动作 | 巡检只产出建议，`execution_readiness` 永不 `READY_AUTO` |
| 7 | 执行完成不等于结果成功 | 复盘的 `execution_status` 与 `outcome_status` 分离 |
| 8 | 结果自动判定只使用预批准标准和完整真实数据 | 四道前置检查 + `DecisionReview` 校验器 |
| 9 | 正式规则、契约和 Ontology 不能由 Agent 自动修改 | `core/enums.py` 是只读镜像；契约测试拦截任何分叉 |
| 10 | 广告 Agent 冻结期间不自动调用 | 默认 FROZEN + `HandoffDirective` 校验器强制 `HUMAN_ONLY` |
