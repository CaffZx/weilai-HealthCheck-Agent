# S5 可靠投递与反馈实施报告

> 日期：2026-07-31  
> 状态：内部实现完成；正式中控联调受外部合同阻断

## 1. 实施结论

S5 已完成纯 `InspectionResultEnvelope` 的事务 Outbox 消费、原包重投、业务 ACK 校验、
最大重试转 DEAD、Feedback Inbox 幂等消费、信号版本校验、合法状态转换和 R7 到期复扫
衔接。所有生产入口默认关闭，未调用生产 MCP 或中控。

现有《巡检 Agent MCP 回传接口接入文档 v1.0》的 `submit_patrol_batch` 强制要求经营模式、
建议、动作和审批字段，违反巡检 Agent 的纯巡检职责边界，因此不能作为本 S5 Result Sink。

## 2. 已实现能力

### 2.1 Result Sink 与 Outbox Worker

- 使用 `t_patrol_delivery_outbox` 中冻结的 `payload_json` 重投，不重新采集事实或生成结论；
- 领取时校验数据库 payload 与创建时 `content_hash` 一致；
- 使用 `outbox_id` 作为幂等键，携带内容哈希；
- HTTP 2xx 后仍严格校验业务 ACK；
- ACK 必须包含匹配的 `event_id`、`accepted=true`，并覆盖 Run、Signal 和 Handoff ID；
- 失败指数退避，达到 `max_retry` 后进入 `DEAD`，保留错误类别；
- 成功后保存完整 `delivery_ack_json` 和 `published_at`。

### 2.2 Feedback Inbox

- `event_id` 唯一；同 ID 同内容返回首次结果，同 ID 不同内容返回幂等冲突；
- 未知 Signal、旧版本和非法状态跳转作为 `REJECTED` 事件留痕；
- `HANDLED` 只转 `AWAITING_RESCAN`，不直接标记事实恢复；
- `OBSERVE_REQUESTED` 转 `OBSERVING`；
- `IGNORED`、`FALSE_POSITIVE` 和 `UNIT_ARCHIVED` 必须提供原因码；
- `ACTION_RECEIPT_AVAILABLE` 仅记录回执引用，不改变状态或版本；
- 状态变化同步写不可变 Occurrence，并使 Signal 版本加一。

### 2.3 到期复扫

- 外部明确提供合法 `next_inspection_at` 时采用外部时间；
- 未提供时按 `inspector/rules/R7_复查频次.yaml` 计算；
- Scheduler 沿用 S2 的 15 分钟到期扫描和经营单元合并；
- 复扫完成时清除已经消费的旧到期时间，避免重复创建到期任务；
- 是否恢复仍由新事实下连续两次未命中决定。

## 3. 数据库变更

新增 revision `0003_feedback_inbox_decoupling`，仅移除 Inbox 到 Signal 的物理外键，使未知
Signal 的拒绝事件也能被审计。应用层仍在同一事务内锁定并校验现有 Signal。

未新增或修改任何 `t_ops_*` 表，也未写入中控执行面。

## 4. 生产安全开关

- `feature_flags.result_delivery_enabled: false`
- `feature_flags.feedback_enabled: false`
- `feature_flags.scheduler_enabled: false`

只有在正式结果接收合同、反馈合同、鉴权和安全联调环境冻结后才能分别启用。

## 5. 外部阻断项

结果接收端需提供不强制经营模式、建议、动作和审批字段的纯巡检 Tool/API，并返回至少：

```text
event_id
accepted
accepted_object_ids
rejected_objects
duplicate
received_at
```

反馈合同需确认事件类型、信号版本语义、原因码、观察时间和 ActionReceipt 引用规则。
在这些条件满足前，S5 只能声明“内部实现完成”，不能声明“生产闭环联调完成”。
