# 复查数据能力说明

## 1. 复查流程

当前复查会重新采集事实并生成新的当前事实快照：

```text
读取基线快照
→ 重新采集事实 MCP
→ 归一化事实
→ 生成 currentFactSnapshot
→ 按中控传入的 successCriteria / failureCriteria 判断
→ 保存复查结果
```

复查不会执行广告、Listing 或库存操作，也不会自动替中控执行批准计划。

## 2. 可以复查的数据

复查标准通过 `metricPath` 指向 `currentFactSnapshot` 中的字段，支持 `GTE`、`LTE`、`EQ` 三种比较方式。

身份字段的首要作用是确认复查仍然针对同一个经营单元。

## 3. 执行回执复核

复查还会比较中控传入的：

- `approvedPlan`
- `executionReceipts`

可以判断批准计划项是否存在有效执行回执。没有生效的计划项会记录到：

```text
executionDeviations
```

巡检侧不会自行推断动作是否执行，必须依赖中控或执行 Agent 提供真实回执。

## 4. 条件可复查或当前不稳定的数据

以下数据取决于外部配置、异步事实或当前采集能力：

| 数据 | 当前行为 |
|---|---|
| 月度目标 | ERP 未配置时为空，相关标准返回 `NOT_EVALUATED` |
| 目标 ACOS | 依赖广告目标配置，缺失时不能判断 ACOS 是否达标 |
| 目标每日预算 | 依赖广告目标配置，缺失时不能判断预算偏差 |
| 净现金回收 | 当前没有完整来源映射，退出/清货可行性不能自动确认 |
| 未来库存覆盖目标 | 依赖未来月份目标和库存数据 |
| 逐日自然流量序列 | 当前默认关闭自然广告流量采集，趋势通常不可用 |
| 子体详情、评论、账号健康 | 依赖异步子体事实 Worker，未完成时会产生待采集缺口 |
| 最新经营模式 | 复查不会重新调用经营模式 Agent，仅可能读取广告配置中的标签 |
| 到手价 | 当前 `price.effective_price` 未被本轮 MCP 覆盖 |

缺失数据不会默认填充为 `0`，也不会默认判定成功。

## 5. 复查不会自动做的事情

当前复查不是完整的“重新跑巡检”，而是：

```text
重新采集事实
→ 生成当前快照
→ 评估中控传入的复查标准
```

它不会自动调用完整的 R2/R3 异常规则重新生成新的异常信号。因此，中控需要在 `successCriteria` 和 `failureCriteria` 中明确提供要验证的指标及阈值。

## 6. 请求标准示例

```json
{
  "criterionId": "acos-recovered",
  "metricPath": "profit.acos_7d",
  "operator": "LTE",
  "target": 0.35
}
```

常用 `metricPath` 示例：

- `sales.avg_daily_units_7d`
- `sales.monthly_completion_rate`
- `traffic.conversion_this_week`
- `profit.acos_7d`
- `inventory.fba_available`
- `inventory.inventory_days_of_supply`
- `quality.star_rating`
- `quality.refund_rate_this_week`
- `price.current_price`

## 7. 复查结果规则

- 数据阻断或指标缺失 → `INCONCLUSIVE`
- 任一失败标准满足 → `FAILED`
- 所有成功标准满足且无执行偏差 → `SUCCESS`
- 只有部分成功标准满足 → `PARTIAL_SUCCESS`

对应的下一步建议：

- `INCONCLUSIVE` → `REPAIR_DATA`
- `FAILED` → `START_NEW_PATROL_CYCLE`
- `SUCCESS` / `PARTIAL_SUCCESS` → `CLOSE_CYCLE`
