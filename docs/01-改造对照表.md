## 5. 数据流对照

**改造前**

```text
本地 SQLite（local_store）
→ anomaly_detector + severity_grader
→ score_calculator（综合执行分 / P0-P2）
→ event_pool（本地公共状态）
→ _build_task_card（自带前端任务卡）
```

**改造后**

```text
MCP（8 个 ERP 工具，并行）
→ FactNormalizer（归一化 + 字段血缘）
→ FactQualityService（缺口判定：阻断 or 降级）
→ FactSnapshotBuilder（冻结 + content_hash）
→ LegacyRuleAdapter → 现有 R2/R3 规则（业务逻辑不变）
→ ModeAgentClient（经营模式，唯一权威）
→ AdvertisingAgentClient（冻结期改为人工交接）
→ PatrolAnalyzer（跨域冲突检查 ← 巡检 Agent 的核心价值）
→ ProposalBuilder（分流：动作 / 观察 / 数据修复）
→ SignalBuilder（四个确定性队列字段 + 交接指令）
→ PackageBuilder → PatrolAnalysisPackage
→ ControlCenterClient（幂等提交；失败落盘重投原包）
→ 中控审批与页面
→ 中控发起复盘 → ReviewOrchestrator（重新采集事实）
→ 回传 DecisionReview
```

## 6. 接口对照

| 旧接口 | 新接口 | 迁移阶段 |
|---|---|---|
| `POST /api/inspect/{key}` | `POST /api/v1/patrol/runs` | 第一阶段并存，第二阶段旧接口标 deprecated |
| `POST /api/inspect/batch` | Scheduler 从 MCP 清单创建 MySQL 批次，或人工逐单元调用 `/api/v1/patrol/runs` | 同上 |
| `POST /api/judge/{key}` | 无对应；LLM 降级为解释性能力，仅人工触发 | 第二阶段限制为开发调试 |
| 无 | `GET /api/v1/patrol/jobs/{job_id}` | 新增：查询 Job 状态；兼容 `/runs/job_*` |
| 无 | `GET /api/v1/patrol/runs/{run_id}` | 新增：查询 Run 与 Outbox 投递状态 |
| 无 | `GET /api/v1/patrol/signals/{signal_id}` | 新增：查询 Signal 当前态与不可变 occurrence 历史 |
| 无 | `POST /internal/v1/reviews` | 新增 |
| 无 | `GET /api/v1/patrol/health` | 新增（内部诊断，不是中控页面数据源） |
