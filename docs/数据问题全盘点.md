# 数据问题全盘点（含 LLM 脑补假设）

> 基于 70 个 ASIN 真实同步数据的空值率实测（2026-7-8）。
> 分四类：A 完全取不到 / B 能取但大量为空 / C 有源未同步 / D LLM 脑补假设。

---

## A. 完全取不到（数据源不存在或无权限）—— 命门

| 数据 | 影响的判定 | 严重度 |
|---|---|---|
| 链接状态（下架/被抑制/不可售） | 链接不可售 | 🔴 S0 判不了 |
| Buy Box 状态 | Buy Box 丢失 | 🔴 S0 判不了 |
| 内容变更记录 + ERP 内容基准 | 主图/标题/五点/图片/A+ 异常 | 内容大类判不了 |
| 平台合规提示/认证状态 | 合规异常 | 🔴 S0 判不了 |
| 促销活动配置 + 前台促销展示 | 促销异常 | 判不了 |
| 超龄库存量/FBA库龄/超龄仓租 | 滞销异常 | 判不了 |
| 子体库存快照（listing_inventory 全空） | 分色库存 | 判不了 |
| 竞品集内本产品卡位 + 近7天卡位基线 | 卡位异常 | 判不了 |
| 变体重要性（主要色/次要色/长尾色） | **基础分二维表取列** | ⚠️ 全局打分受影响 |

> 变体重要性尤其关键：知识库的基础分是「严重度 × 变体重要性」二维表，没有这个标签，所有变体级异常的基础分都取不准。

## B. 工具能返回，但真实数据大量为空（判定打折）

| 字段 | 有值率 | 影响 |
|---|---|---|
| 每日 ACOS | **50%** | 无广告花费的天 ACOS 为空，连续天数判定样本不足 |
| 每日毛利率 | 61% | 毛利判定部分缺 |
| 类目平均转化率 | **45%** | 链接转化率异常「基准B（vs类目）」一半产品做不了 |
| 目标评分 TARGET_STAR_RATE | 78% | 评分异常「基准B（vs目标）」22% 产品做不了 |
| 月度目标销量 | 73% | 目标偏离 27% 产品无目标可比 |
| az_extend·STOCK_INVENTORY | **0%** | 父级记录该字段空，库存靠 stock_summary 兜 |
| az_extend·PRODUCT_GRADE | **0%** | 产品等级取不到（定位靠 ERP config 的 position） |
| az_extend·STAR_LEVEL | 0% | 当前星级靠 listing_baseline.星级（90%）兜 |
| az_extend·上架日 ASIN_START_SALE_DATE | **1%** | 新品判定（库存积压/滞销的「上架不足30天」）几乎做不了 |

## D. LLM 脑补 / 假设的数据（最危险，判定不可靠）⚠️

当规则需要某基线但数据缺失时，LLM 不会报错，而是**自己编一个值继续判**。已实际观察到的：

| LLM 假设的内容 | 真实情况 | 后果 |
|---|---|---|
| **「近7天平均ACOS假设约30%」** | 已同步 ASIN 现在提供真实基线；**未同步 ASIN 仍会假设** | ACOS 异常严重度可能判错 |
| **「目标ACOS未提供，按默认30%估算」** | ERP config 里有 `target_acos_suggest`（如25/40），LLM 有时忽略不用 | 目标类判定偏差 |
| **定位 T 层映射错**（把 P2_PRODUCT 读成 T3 长尾，应是 T2 常规） | config 是 P2_PRODUCT=T2 | 定位系数用错（1.0 vs 0.6），分数全偏 |
| **「连续≥3天」不严格数天** | 规则要求逐日核对连续天数 | LLM 是「看着像恶化」就判，非精确计数 |
| **类目平均转化率缺失时自行假设** | 45% 产品无此值 | 转化率基准B 结论不可信 |
| **目标评分缺失时假设 4.0 左右** | 22% 产品无目标评分 | 评分基准B 不可信 |
| **差评「近14天新增」凭文本猜** | 无评论时间戳 | 差评时效判定靠猜 |
| **打分数学 LLM 心算** | 基础分×定位×阶段×淡旺季+并发 | 234/140 等分数未经严格计算，有算错风险 |
| **卡位/自然流量趋势编造** | 卡位数据取不到、自然占比每日未同步 | 若判这两类异常基本是编的 |

### 为什么危险
- LLM 假设**不会告诉你它在假设**（除非碰巧写进 reason）
- 同一个 ASIN 两次判定结果可能不同（定位 T2/T3 反复、分数波动）
- **打分和排序交给 LLM 心算，违背方案「打分必须可复现可审计」的铁律**

---

## 一句话结论

**现在能相对可信判定的**：目标偏离、退款异常、库存积压、库存可售（数据齐、基线明确）。
**判定不可信的**：一切涉及「连续天数精确计数、打分数学、缺失基线、变体重要性、链接状态、卡位」的场景 —— LLM 在这些地方靠假设填空。

**根治方向**：把打分/阈值映射/连续天数从 LLM 手里收回给代码（rule_engine），LLM 只留「识别 + 查因 + 写文案」。缺失基线要么补数据源（命门），要么在 prompt 里明确告诉 LLM「缺 X 时不要假设，直接标数据不足」。
