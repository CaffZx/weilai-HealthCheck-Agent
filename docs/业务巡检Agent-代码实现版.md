## 模块 0　知识库总则

### 0.1 知识库范围与模块导览（执行顺序）

本知识库为业务巡检 Agent 的判定与处理真相源，覆盖模块 0–7，Agent 按以下顺序执行：

| 模块 | 职责 | 产出 |
| --- | --- | --- |
| 模块 1 | 抓取产品标签与动态判定基线 | 标签、系数、判定基线 |
| 模块 2 | 异常字典：定义每个异常”是什么”、作用层级、跳过规则、所需数据字段索引 | 异常点位命中结果 |
| 模块 3 | 将命中的异常映射为严重度 S0/S1/S2 | 异常严重度 S |
| 模块 4 | 执行分数计算与优先级映射 | 执行优先级 P0/P1/P2 |
| 模块 5 | 升降级与解除规则 | 任务状态调整 |
| 模块 6 | 表现型异常原因查证（6.0）与处理建议库（6.2/6.3） | 原因说明 + 处理建议 |
| 模块 7 | 运营输出规范（父 ASIN 任务卡） | 任务卡 |

事件状态流转、长期跟进流程、等属系统机制与落地范畴，归方案文档处理，不纳入本知识库。**各异常点位的巡检频次（每日 / 每周 / 指定周期扫描节奏）不在本知识库定义，统一由独立的巡检频次规则文件维护；本知识库只定义每个异常是什么、如何判定、严重度、处理建议与复查 / 解除逻辑。**

复查时间优先规则（全局）：若运营为某个异常设置了复查时间，则该异常的复查以运营设置时间为准，覆盖模块 5.3 与模块 7 的默认复查规则；运营未设置时，按模块 5.3 与模块 7 的默认复查规则执行。


## 模块 1　产品标签与判定基线抓取

本模块不负责给产品打标签，也不负责计算经营指标——产品定位、阶段、淡旺季、变体重要性等标签的赋值由上游 ERP/打标系统完成；近 7 天平均 ACOS、近 7 天平均花费等动态经营数据由系统计算或从 ERP 抓取。本系统只做三件事：抓取这些输入，定义标签如何映射成执行分数的系数，以及定义动态判定基线如何影响异常判定口径。因此本模块只保留”输入项 → 系数/影响”的对照，不复述上游的判定阈值或准入条件。

### 1.4 动态判定基线：近 7 天平均 ACOS / 近 7 天平均花费

近 7 天平均 ACOS 与近 7 天平均花费不属于产品标签，而是系统按该产品过去 7 天广告表现计算出的动态判定基线。它们本身不是异常，也不进打分权重，仅作为广告类异常的判定基线：当前 ACOS / 花费相对近 7 天平均值偏离到一定程度才算异常并判定严重度，判定细则见模块 3.6。近 7 天平均 ACOS 用于 ACOS 异常判定；近 7 天平均花费用于广告花费异常判定。注意：近 7 天平均花费不是”预算设置值”。广告花费异常判断的是实际花费相对过去 7 天平均花费的偏离，不是预算额度本身的变化。

### 1.5 变体重要性（子体级标签）

由 ERP 对父 ASIN 下每个子体（颜色）打好的分类，本系统直接抓取，用于**变体级异常**的基础分取列（模块 4.1）。仅对变体级异常生效，链接级异常不适用；库存类异常（FBA 可售库存为 0、库存不足）在子体层识别，同样按命中子体的变体重要性取列，见模块 2.0（其巡检频次由巡检频次规则文件统一维护）。

| 变体重要性（ERP 值） | 说明 |
| --- | --- |
| 主要色 | 流量入口颜色，承担主要流量与销量 |
| 次要色 | 销售占比稍高的颜色 |
| 长尾色 | 重要度很低的颜色 |

同一变体级异常（如主图异常、FBA 可售库存为 0）命中不同重要性的变体，严重度相同但基础分不同：主要色 > 次要色 > 长尾色（见模块 4.1）。库存类异常同样适用本差异。


## 模块 2　异常字典（分类与问题点位）

系统能识别的全部异常清单，Agent 识别与运营理解共用，共 7 大类。本字典只做一件事——**把每个异常”是什么”定义清楚**：每个大类给”定义 + 边界”，每个问题点位只给定义。

范围约定：

- **具体字段的工程实现口径**由工程侧维护，不在本知识库定义；各点位所需数据字段的业务级清单见模块 2.8 异常点位主索引表，来源统一写为 ERP / 平台后台 / 广告后台 / MCP 接口，不编造具体表名。

- 本模块中涉及的默认识别阈值为业务初始值，可在影子期 / 运营反馈后统一校准；本知识库正文中的阈值为当前生效值。

异常大类总览：本模块共定义 7 个异常大类，分布如下。其中交易表现类、售后异常类为”表现型异常”（需经模块 6.0 原因查证），其余为”现象即原因型”（直接处理）。

| 序号 | 异常大类 | 关注什么 | 类型 |
| --- | --- | --- | --- |
| 1 | 链接状态异常 | 链接能否正常展示/购买/销售、成交主导权 | 现象即原因型 |
| 2 | 内容完整性异常 | 页面内容是否完整、能否承接流量转化 | 现象即原因型 |
| 3 | 价格与促销异常 | 价格促销是否正常承接成交 | 现象即原因型 |
| 4 | 库存与可售异常 | 库存能否支撑继续销售 | 现象即原因型 |
| 5 | 交易表现异常 | 转化/销量/广告等结果指标 | 表现型（需查证） |
| 6 | 合规与属性异常 | 是否存在平台规则风险 | 现象即原因型 |
| 7 | 售后异常 | 差评/评分/退款等售后信号是否影响买家信任与经营 | 表现型（需查证） |

### 2.0 异常作用层级（决定基础分取列）

每个异常按作用层级分类，决定模块 4.1 基础分取哪一列：

- **变体级异常（命中具体子体，按命中变体的主要色/次要色/长尾色取列）**：链接不可售、变体掉线、变体价差异常、主图异常、图片异常、A+ 异常、Buy Box 丢失、FBA 可售库存为 0、库存不足、合规异常，以及类目异常、属性信息异常中明确命中具体子体的情况。其中：链接不可售在子体层识别（每个子 ASIN 有各自前台展示与后台可售状态），按命中子体变体重要性取列并按 2.0.1 分层跳过；库存类异常（FBA 可售库存为 0、库存不足）在子体层识别、按命中子体变体重要性取列（其巡检频次由巡检频次规则文件统一维护，不在本知识库定义）。

- **链接级异常（整条链接的事，不分变体，取链接级异常基础分列）**：以上之外的全部点位（父子体关系异常、标题异常、五点异常、促销异常、链接转化率异常下降、销量异常、ACOS 异常、广告花费异常、目标偏离、自然流量异常、卡位异常、放量未执行、库存积压、滞销异常、近期集中差评、评分异常、退款异常）。

合规与属性异常的层级规则：**合规异常固定为子体级（变体级）异常**，命中对象记录到具体子 ASIN，按命中子体的变体重要性取列；若平台合规限制作用于该父 ASIN 下全部子体，则按”全部子体命中”处理，视同波及主要色（基础分取主要色列，表现型巡检跳过规则按 2.0.1 执行）。类目异常、属性信息异常默认按实际命中对象判定：仅命中某个具体子体/变体字段的按变体级处理；影响父体整体、整条链接展示或平台审核的按链接级处理。

父子体关系异常的取列规则：该点位仅指父体被拆、全部子体从原父体结构中掉出，属于父体结构级 / 链接级异常；命中对象标注为父体 / 全部子体，基础分取链接级 S0=100，不再按主要色 / 次要色 / 长尾色拆分。

关于 ACOS / 广告花费 / 销量（父体级数据）：这三个指标取的是整个父体（所有变体的汇总集合）的数据——看的是整条链接的广告花费、ACOS、单量，不是某一个变体的。它们天然没有”哪个变体”的概念，因此归入链接级、不分变体重要性，基础分取二维表的链接级异常基础分列。

通用规则（兜底）：异常若被识别为发生在某个具体子体上，按该子体的变体重要性取列；发生在父体/Listing 整体的，按链接级异常基础分列取。上述清单为常见默认归类，实际命中对象与默认不一致时以通用规则为准；合规异常一律维持子体级，不适用链接级兜底。

异常类型（决定是否需要原因查证）：异常按是否需要原因查证分两类——表现型异常 = 模块 2.5 交易表现类 + 模块 2.7 售后异常类的全部点位（统计数字/比率/文字反馈，现象不等于原因，背后有多个可能原因，需经原因查证（模块 6.0）过滤出真实原因后再处理）；现象即原因型异常 = 以上之外的全部点位（现象本身即明确原因，或由平台直接给出，无需查证，直接按处理建议处理）。本规则按大类绑定：2.5、2.7 新增的点位自动归为表现型。例外：放量未执行虽列于模块 2.5，但属”该做没做型”异常——放量条件全部满足本身即结论，按现象即原因型处理，不进入模块 6.0 原因查证，处理建议见模块 3.12。

### 2.0.1 表现型异常巡检跳过规则

部分非表现型异常一旦命中，说明该链接（或该子体）已丧失正常展示或成交能力，此时表现型异常（销量、ACOS、广告花费、转化率、自然流量、卡位、售后等）的数据已失真甚至归零，继续巡检与查因无意义。命中下表标注”跳过”的点位时，本轮巡检跳过对该链接（或该子体，视命中层级而定）表现型异常的独立判定与查因；命中”不跳过”的点位时，表现型异常巡检正常进行，可正常触发模块 3.3.1 共因上调规则。判断标准：该异常发生时链接是否仍能正常展示、被浏览、被下单——不能则跳过，仍能则不跳过（与严重度高低无关）。

分层跳过原则（按命中对象）：下表跳过点位分三类。

① **无条件跳过**——父子体关系异常：父体被拆、全部子体掉出，父体级表现型数据失真，一律跳过。

② **按命中变体重要性分层**——链接不可售、Buy Box 丢失、主图异常、合规异常、变体掉线、FBA 可售库存为 0：命中主要色则跳过，命中次要色/长尾色则不跳过。级联规则：主要色命中②类点位时，因表现型异常为父体级汇总数据、已整体失真，跳过整个父 ASIN 的表现型巡检，其余次要色/长尾色不再单独触发；次要色/长尾色命中时，父体汇总仍由主要色撑住、数据仍有意义，不跳过父 ASIN，该变体问题按变体级异常单独处理，或作为查因中的并发原因（见模块 6.0）。若为整条 Listing / 全变体一起命中（无单一命中变体可分层），视同波及主要色，跳过。

③ 库存类异常（FBA 可售库存为 0）已并入②类，按命中子体的变体重要性分层跳过（主要色命中跳过、次要色/长尾色命中不跳过），与其它变体级状态类异常一致。

| 大类 | 异常点位 | 是否跳过表现型巡检 / 依据 |
| --- | --- | --- |
| 2.1 链接状态 | 链接不可售 | 主要色命中跳过 / 次要色·长尾色命中不跳过 —— 命中子体前台失效或后台不可售，无法正常展示/购买 |
| 2.1 链接状态 | Buy Box 丢失 | 主要色命中跳过 / 次要色·长尾色命中不跳过 —— 直接影响成交 |
| 2.1 链接状态 | 父子体关系异常 | 跳过 —— 父体被拆、全部子体掉出，父体级表现型数据失真 |
| 2.1 链接状态 | 变体掉线 | 视命中变体而定 —— 主要色掉线跳过（核心成交能力受损、表现型数据失真）；非主要色掉线不跳过（其余子体仍正常在售，链接整体仍可展示购买）。部分子体掉出统一归入本点位 |
| 2.2 内容完整性 | 主图异常 | 主要色命中跳过 / 次要色·长尾色命中不跳过 —— 主图缺失或错图，缺图时搜索中不可见/不可识别 |
| 2.2 内容完整性 | 图片异常 | 不跳过 —— 仍可购买展示 |
| 2.2 内容完整性 | 标题异常 | 不跳过 —— 仍可购买，只影响匹配/点击 |
| 2.2 内容完整性 | 五点异常 | 不跳过 —— 不影响展示购买能力 |
| 2.2 内容完整性 | A+ 异常 | 不跳过 —— 不影响展示购买能力 |
| 2.3 价格与促销 | 变体价差异常 | 不跳过 —— 不影响展示购买能力 |
| 2.3 价格与促销 | 促销异常 | 不跳过 —— 不影响展示购买能力 |
| 2.4 库存与可售 | FBA 可售库存为 0 | 主要色命中跳过 / 次要色·长尾色命中不跳过 —— 主要色断货时已丧失核心成交能力 |
| 2.4 库存与可售 | 库存不足 | 不跳过 —— 尚可成交，仅有断货风险 |
| 2.4 库存与可售 | 库存积压 | 不跳过 —— 不影响成交能力 |
| 2.4 库存与可售 | 滞销异常 | 不跳过 —— 不影响成交能力 |
| 2.6 合规与属性 | 类目异常 | 不跳过 —— 仅影响识别/曝光，未实际受限 |
| 2.6 合规与属性 | 属性信息异常 | 不跳过 —— 同上 |
| 2.6 合规与属性 | 合规异常 | 主要色命中跳过 / 次要色·长尾色命中不跳过 —— 已命中平台合规限制；全部子体命中视同波及主要色，跳过 |
| 2.5 交易表现 / 2.7 售后 | 该两大类全部点位 | 不适用 —— 本身即”表现型异常”，是被判断的对象，不参与本规则 |

各点位严重度以模块 3.3 判定表为准，本表不重复定义严重度，仅定义是否跳过。

每轮巡检独立判断：命中跳过清单的非表现型异常，在该异常存续期间（未被运营标记解决 / 未自动恢复关闭），每轮巡检持续跳过对应表现型异常的独立判定与查因；该异常解除后，自下一轮巡检起恢复正常判断，包括是否触发新的非表现型异常、以及是否需要再次命中跳过清单。是否跳过为每轮巡检独立判定的动态结果，非一次触发后静态锁定。

跳过时的任务卡填写：命中跳过清单时，任务卡”判断依据 / 数据”栏只填该非表现型异常自身实际检测到的事实，不得填写”经营指标同步下滑”等未经检测的推测或具体经营数值（详见模块 7.0）。

### 2.1 链接状态异常

**定义：产品链接在前台展示、购买路径、在售状态、父子体结构或平台状态上出现异常，导致链接无法正常展示、无法正常下单，或存在影响正常销售的状态风险，或链接的成交主导权（Buy Box）异常。**

**边界**：判断链接本身是否还能正常展示、正常购买、正常销售。

| 问题点位 | 定义 |
| --- | --- |
| 链接不可售 | 链接前台无法作为正常在售商品展示，或后台状态不再属于正常可售范围。例如前台变狗、页面失效等；后台 ASIN 显示的字段为不可售、已禁止显示搜索结果或报价缺失。边界：链接前台失效 / 后台状态非可售导致的无法正常展示或购买，均归本点位；库存状态不可用（如被冻结、禁止显示、不可履约）导致的不可售，其后台状态同样表现为不可售，亦归本点位捕获；库存数量维度问题（可售库存为 0、库存不足）归 2.4。作用层级：每个子 ASIN 都有各自的前台展示与后台可售状态，本点位在子体层识别、命中记录到具体子 ASIN，属变体级异常，按命中子体的变体重要性取列（模块 4.1），并按 2.0.1 分层跳过（主要色命中跳过、次要色/长尾色命中不跳过）。 |
| 变体掉线 | 原本挂在父体下的**单个或部分子体**脱离父体，导致买家无法在父体变体中选择该子体，但父体结构整体仍存在。边界：只要父体结构仍在、掉出的是部分子体（含原”父子体关系异常 · 部分子体掉出”场景），一律归本点位，不归父子体关系异常。 |
| 父子体关系异常 | **父体被拆，全部子体从原父体结构中掉出**，父体和子体关系异常，影响变体展示或销售。边界：仅当父体结构被拆散、全部子体掉出时归本点位；部分子体掉出归”变体掉线”。两点位互斥，同一现象不得同时命中。 |
| Buy Box 丢失 | 商品未获得 Buy Box（链接仍在售，但未拿到黄金购物车，直接影响成交）。 |

### 2.2 内容完整性异常

**定义**：产品链接页面中的核心内容出现缺失、错误、展示异常或审核异常，导致买家无法完整理解产品信息，进而影响点击、转化或页面承接能力。

**边界**：判断页面内容是否完整，是否具备承接流量和转化的基础。

| 问题点位 | 定义 |
| --- | --- |
| 主图异常 | 状态可检测项：主图缺失、不符合平台规则被禁止显示、审核不通过或前台展示异常（以平台后台状态 / 展示抓取结果为判定依据） |
| 图片异常 | 副图数量＜3 张，副图未通过审核或展示异常。 |
| 标题异常 | 状态可检测项：标题缺失、审核不通过或不符合平台规则。 |
| 五点异常 | 五点缺失、数量不足五条、信息不完整。 |
| A+ 异常 | A+ 缺失、未展示或审核异常。 |

### 2.3 价格与促销异常

**定义**：产品当前售价、Coupon、促销活动、折扣展示或活动价格出现异常，导致链接转化下降、利润异常、Buy Box 风险增加，或销售节奏受到影响。

**边界**：判断价格和促销是否正常承接流量，是否影响成交效率。

| 问题点位 | 定义 |
| --- | --- |
| 变体价差异常 | 同一父 ASIN 下，各变体前台到手价差距明显偏离正常价格带，可能影响买家选择、链接动销、广告承接或主推变体转化。比价基准：以主流量入口颜色（主要色）中价格最低尺码的前台到手价为基准。默认识别阈值与命中规则：① 尺码分支——主要色内其他尺码到手价相对基准差距 ≥40% 且绝对差距 ≥$5，命中对象记录到价格偏离的尺码子体，基础分按主要色列取（模块 4.1）；② 颜色分支——其他颜色各子体到手价相对基准差距 ≥70% 且绝对差距 ≥$14，命中对象记录到价格偏离的颜色子体，基础分按该子体变体重要性取列。若价差由活动价、Coupon、清货策略、少库存控速等运营动作导致，则标记为”需运营复核”：不输出正式 S0/S1/S2、不进入模块 4 打分，仅在任务卡输出板块展示”需运营复核”及价差数据；非运营动作导致的价差按正式异常输出（S1，见 3.3）并正常进入打分。 |
| 促销异常 | ERP 系统活动配置存在但前台未展示对应促销信息；促销活动（秒杀、LD、Z 划算、Coupon 等）未生效、折扣错误，或前台展示与 ERP 配置的活动类型不一致。 |

### 2.4 库存与可售异常

定义：产品库存状态、FBA 可售库存、库存承接能力或前台可购买状态出现异常，导致链接无法正常成交，或存在短期断货、推广无法承接的风险。

边界：判断库存是否能支撑链接继续正常销售。FBA 可售库存为 0 / 库存不足在子体层识别、按命中子体的变体重要性取列（主要色 / 次要色 / 长尾色，见模块 2.0、4.1）。本类异常的巡检频次（扫描节奏）由巡检频次规则文件统一维护，不在本知识库定义；复查以运营设置时间优先，未设置时按模块 5.3、模块 7 默认复查规则执行。

| 问题点位 | 定义 |
| --- | --- |
| FBA 可售库存为 0 | FBA 当前可售库存为 0，已无法承接后续销售，属于实际断货。 |
| 库存不足 | FBA 当前可售库存大于 0，但低于未来 14 天预计消耗（过去 7 天日均销量 ×14），存在短期断货风险。 |
| 库存积压 | 可售库存相对近期消化能力和未来目标消化能力明显偏高，存在库存占压、滞销或长期仓储费风险。具体按”可售天数 + 未来目标累计”双指标交叉判定，分级见模块 3.13。 |
| 滞销异常 | 已产生超龄仓租，且超龄库存短期无法消化、费用损失达到规模的库存异常。该点位只看超龄库存是否卖得掉，与库存积压看整体可售库存不同；准入与分级见模块 3.14。子 ASIN 查、父 ASIN 汇总。 |

### 2.5 交易表现异常

定义：链接在销量、订单、曝光、点击、转化率、广告成交、自然订单占比、卡位等经营指标上出现异常波动，说明链接当前流量获取能力、成交能力或流量承接能力出现问题。

边界：判断链接是否还能正常获得流量并完成成交。本类异常除放量未执行外均为表现型异常，现象不等于原因；触发后需进入模块 6.0 进行原因查证，确认真实原因后再输出处理建议。例外：放量未执行属现象即原因型（条件满足本身即结论），不进入模块 6.0 查因，直接按模块 3.12 的处理建议输出。

| 问题点位 | 定义 |
| --- | --- |
| 链接转化率异常下降 | 链接转化率（整条链接，链接级）较历史水平或类目平均水平明显下降，说明链接成交承接能力变弱。按周维度判定，分级见模块 3.10。 |
| 销量异常 | 当前销量较过去 7 天日均连续 ≥3 天大幅偏离。下降方向作为销量异常，关注销量下滑、断货、掉权或转化问题；上升方向作为”销量增长提示”，用于提示链接出现增长信号。若同时满足”放量未执行”条件，则不单独输出销量增长提示，转入”放量未执行”。分级见模块 3.6。 |
| ACOS 异常 | 实际 ACOS 连续 ≥3 天明显高于该产品过去 7 天平均 ACOS，说明广告投入产出效率变差。分级见模块 3.6。 |
| 广告花费异常 | 实际广告花费连续 ≥3 天明显偏离过去 7 天平均花费，包括花费超出和花费不足两个方向。分级见模块 3.6。 |
| 目标偏离 | 实际单量连续低于运营在 ERP 设定的日均目标单量或月目标节奏，说明当前销售结果未达到运营目标。分级见模块 3.7。 |
| 自然流量异常 | 自然订单占比连续低于近 7 天平均水平，说明链接自然流量贡献走弱。按三窗口判定，分级见模块 3.8。 |
| 卡位异常 | 本产品在直接竞品集合中的排位下滑，说明竞争入口位置变弱，可能进一步影响自然流量和销量。分级见模块 3.9。 |
| 放量未执行 | 产品已满足放量条件，但广告投入未跟上，属于”该做没做型”机会损失异常。判定见模块 3.12。 |

### 2.6 合规与属性异常

定义：产品链接因类目、属性、平台规则、合规字段、认证要求、敏感表达或页面字段问题，存在被限制、被抑制、审核失败、下架或影响系统识别的风险。

边界：判断链接是否存在平台规则风险，是否会影响链接安全和系统识别。若问题表现为页面内容缺失、错图、标题 / 五点 / A+ 信息不完整，归 2.2 内容完整性异常；若问题由平台规则、敏感表达、合规要求、类目 / 属性识别错误导致，归本类。

| 问题点位 | 定义 |
| --- | --- |
| 类目异常 | 商品类目被错误修改，或类目与产品实际不匹配，影响平台识别、曝光或合规判断。 |
| 属性信息异常 | 颜色、尺码、材质、适用场景等属性缺失、错误或与产品实际不一致，影响系统识别、筛选曝光或买家理解。 |
| 合规异常 | 商品已经命中平台合规要求、认证要求、禁售 / 限售规则，或后台已有明确合规提示，需要修复后才能降低限制风险。作用层级为子体级（变体级），命中对象记录到具体子 ASIN，见模块 2.0。 |

### 2.7 售后异常

定义：产品近期在差评、评分、退款等售后维度出现异常变化，可能影响买家信任、链接转化与长期经营。售后异常为表现型异常——现象（差评数 / 评分 / 退款率）不等于原因，需由 Agent 读取评论内容、退款理由等文字，归类出真实原因（尺码 / 质量 / 物流 / 页面描述等）。

边界：判断差评、评分、退款等售后信号是否已经影响或即将影响买家信任、链接转化与长期经营。售后异常只判断售后表现是否异常，具体原因需进入模块 6.0 读取评论内容或退款理由后确认。

| 问题点位 | 定义 |
| --- | --- |
| 近期集中差评 | 满足以下任一条件即触发：① 14 天内新增低星（≤3 星）评论 ≥3 条，且其中 ≥60% 集中指向同一类问题（尺码 / 质量 / 物流 / 描述不符等，由 Agent 读取评论内容归类判断）；② 14 天内新增负面反馈数量 > 现有评分数的 20%。两个阈值（3 条、60%、20%）为初值，可在影子期 / 运营反馈后校准。 |
| 评分异常 | 当前评分较近期平均评分下降，或低于运营设定的目标评分，说明买家信任信号变弱。按双基准判定，分级见模块 3.11。 |
| 退款异常 | 退款率较自身历史水平或类目平均水平明显升高，说明售后风险或产品承接问题上升。按周维度双基准判定，分级见模块 3.11。 |

## 模块 3　异常严重度判定规则

把异常条件映射为异常严重度 S0/S1/S2，即执行分数的基础分。本模块产出的一律是 S（异常严重度），不是执行优先级 P。

### 3.1 严重度通用定义

严重度只描述”异常本身有多严重”，不含产品定位与变体重要性；基础分由严重度与异常作用层级 / 变体重要性共同决定，见模块 4.1 二维表。

| 严重度 | 含义 | 典型场景 |
| --- | --- | --- |
| S0 | 链接已经无法正常销售，或正在产生直接销售损失、重大合规风险、严重交易中断风险。 | 需立即处理；必须人工介入；当天响应。典型如链接不可售 / 下架、核心成交对象断货 / 严重库存不足、Buy Box 丢失影响订单、合规高风险。 |
| S1 | 链接仍可售，但异常已经明显影响流量、转化、订单、评价或运营效率。 | 内容关键项异常、转化骤降、ACOS 明显超标、库存压力明显。 |
| S2 | 链接短期仍可正常销售，但已经出现轻度异常或风险苗头，影响轻或需观察。 | 次要内容异常、轻微价格偏离、评价需观察、轻度库存压力。 |

基础分（含变体重要性）见模块 4.1。判定步骤：先按本模块定严重度 S0/S1/S2，再按异常作用层级与命中变体重要性，在模块 4.1 二维表取对应基础分。


(3.2 通用判定原则为 LLM 侧边界判断依据,收录于知识库,本文件不重复。)

### 3.3.1 共因严重度上调规则（波及面上调）

规则主体：部分固定严重度的异常点位，若经模块 6.0 查因确认，是 3 个及以上表现型异常的共同真实原因，则该点位严重度在初判基础上上调一档（S2→S1、S1→S0；S0 为封顶档，不再上调）。此上调用于体现该异常已波及多项经营指标、实际影响面大于其孤立形态。

适用点位清单（共 7 个）：图片异常、五点异常、A+ 异常、变体价差异常、促销异常、类目异常、属性信息异常。已为 S0 封顶的点位（如主图异常、标题异常、合规异常等）不适用本规则，因其已无上调空间。售后异常大类下的”近期集中差评”不纳入本清单（该点位本身属表现型/售后大类，为避免与模块 6.0.7 查因逻辑交叉，排除在外）。

基础分取值：严重度经共因上调后，模块 4.1 异常基础分按上调后的新档位（如 S0）取值，不再按原判档位（如 S1）计分；上调结果同步进入模块 4 的执行分数计算与优先级映射。

层级匹配规则：根因为链接级时，正常计入父体级表现型异常的共因计数；根因为变体级时，仅当命中的子体为主要色 / 核心成交变体时，才可计入父体级表现型异常的共因数；命中次要色 / 长尾色的变体级根因，不计入共因上调判定（因次要色 / 长尾色占比过小，难以真实拖累整条链接的父体级汇总表现）。库存类异常（FBA 可售库存为 0、库存不足）作为变体级根因，同样按此规则：命中主要色 / 核心成交变体时计入共因计数，命中次要色 / 长尾色不计入。

各点位默认作用层级引用模块 2.0：图片异常、变体价差异常、A+ 异常为变体级；五点异常、促销异常为链接级；类目异常、属性信息异常按模块 2.0 通用规则兜底判定（命中具体子体按变体级，影响父体 / Listing 整体按链接级）。本清单不重复定义层级，一律以模块 2.0 为准。

共因归属唯一性：同一个表现型异常只能被查因确认归属于一个根因。若同一轮巡检出现多个候选根因都指向同一表现型异常，取证据最直接 / 最先命中的一个作为唯一归属，其余候选不得将该表现型异常重复计入各自的共因计数，避免同一份下游影响被重复利用、导致多个根因被不当上调。

说明：本规则”3 个共因”阈值为初始值，可在影子期 / 运营反馈后校准。上调属模块 5.0”恶化不单列”范畴的默认行为，不属于模块 5.1 硬跳档，无需人工标记或额外审批。


### 3.4 数据不足 / 样本不足 / 不触发正式异常规则

本规则用于约束 Agent 在字段缺失、样本量不足或外部数据不可用时的行为，避免用不完整数据硬判 S0/S1/S2。各专项规则中已定义的数据完整性要求优先适用；本节作为全局兜底。

| 情况 | 处理规则 | 输出要求 |
| --- | --- | --- |
| 缺少关键字段，无法判断异常是否成立 | 不输出正式 S0/S1/S2，不进入执行优先级打分 | 输出”数据不足 / 待补充”，列明缺失字段。 |
| 缺少辅助字段，但异常成立条件已满足 | 可以输出正式异常，但原因查证标注不完整 | 任务卡中标注”部分查证数据不足”，不阻断处理建议。 |
| 样本量不足 | 不输出正式异常，进入观察 | 输出”样本不足观察”，不生成 P0/P1/P2 主任务。 |
| 外部数据缺失（竞品、市场、类目均值等） | 不阻断内部异常判定，只影响外部原因查证 | 输出内部已成立原因；外部原因标注”数据缺失，未完成查证”。 |
| 数据缺失反复发生 | 视为系统 / 数据源问题，反馈工程侧补字段或修接口 | 输出”数据源异常 / 字段缺失待补充”，不由运营按业务异常处理。 |

全局字段缺失规则：若某专项判定所需字段在正常业务逻辑下应同步存在，但实际抓取为空、未生成或缺失，则视为数据源 / 字段缺失问题，不在对应异常点位内单独制定缺失规则；统一按本节输出”数据不足 / 字段缺失待补充”，并列明缺失字段，不输出正式 S0 / S1 / S2 异常。

新品无投放 / 无可售库存下的部分经营判断豁免规则：以父 ASIN 为维度，若产品处于新品阶段，且近 3 天父 ASIN 汇总广告花费均 < $10，同时父 ASIN 汇总可售库存 = 0，则不输出销量异常、ACOS 异常、广告花费异常、目标偏离、自然流量异常、卡位异常、放量未执行、库存不足、库存积压、滞销异常等经营节奏 / 库存压力类异常。此处可售库存 = 0 仅作为过滤条件，不作为主异常输出；Agent 应重点检查链接基础健康问题，包括链接状态、内容完整性、价格与促销、合规与属性等。该规则不豁免链接转化率异常和售后异常：若链接转化率已有有效数据并满足样本量门槛，仍按 3.10 判定；若评分、差评、退款等售后数据已生成，仍按 2.7 / 3.11 判定。

专项规则覆盖：ACOS 样本量门槛、转化率空值 / 样本量门槛、评分空值、退款数据完整性、库存积压未来目标缺失、滞销超龄字段缺失等，均按各自专项规则执行；未被专项覆盖的数据不足场景，按本节兜底处理。

### 3.5 子体判定 → 父卡归集

链接巡检从子 ASIN（子体）层面出发，但通知与处理以父 ASIN 归集成一张任务卡。完整链路：

- 逐子体识别：Agent 对每个子 ASIN 检查，异常事件的明细对象记录到具体子体（如”黑色 / M 码”）。

- 子体判严重度与基础分：对每个子体异常定严重度（S0/S1/S2）；变体级异常按该子体的变体重要性（主要色 / 次要色 / 长尾色）在模块 4.1 取基础分（含库存类异常）；链接级异常取链接级列。

- 子体算执行分数：基础分 × 定位 × 阶段 × 淡旺季（模块 4）。超期不进打分，由模块 5 升降级规则处理。

- 父卡归集：同一父 ASIN 下所有子体异常归集成一张任务卡，卡的执行分数按”最高分主导 + 并发加成”聚合。

- 父卡严重度取子体最高：父卡对外严重度 = 该父 ASIN 下所有子体异常中最高的一个。

- 保留子体明细：卡内列出每个子体异常明细 + 各自变体重要性 + 各自严重度，归集不丢”具体哪个变体出事”的信息。

一句话：严重度先在子体 / 链接层判定；若为变体级异常，再按命中子体的变体重要性在模块 4.1 取基础分；最终分数与通知在父体层聚合，取最高、留明细。

### 3.6 广告与销量类异常专项判定（ACOS / 广告花费 / 销量）

广告类异常以产品近 7 天平均 ACOS、近 7 天平均花费为基线（由系统按历史数据计算、随标签抓取）；销量类异常以过去 7 天日均销量为基线。判定结果为异常严重度，作为基础分进入打分。

触发前提：ACOS、广告花费、销量异常均需连续 ≥3 天满足下表偏离条件才触发，避免单日波动误报；连续天数越长、偏离越大，严重度越高。

（1）ACOS 类异常

ACOS 异常样本量前置规则：ACOS 异常在满足”实际 ACOS 连续 ≥3 天超出近 7 天平均 ACOS”的基础上，还必须满足最低样本量条件，才输出正式异常。最低样本量满足以下任一条件即可：① 近 3 天累计广告花费 ≥ 近 7 天日均花费 × 3 × 50%；② 近 3 天累计点击 ≥ 20 次。若连续 ≥3 天 ACOS 超标但不满足最低样本量条件，则不输出正式 ACOS 异常，仅标记为”ACOS 样本不足观察”。

| 实际 ACOS 相对近 7 天平均 ACOS（连续 ≥3 天） | 异常严重度 |
| --- | --- |
| 超出 0–30% | 不预警（正常波动） |
| 超出 30–60% | S2 |
| 超出 60–100% | S1 |
| 超出 >100% | S0 |

（2）花费超出

| 实际花费相对近 7 天平均花费（连续 ≥3 天） | 异常严重度 |
| --- | --- |
| 超出 0–30% | 不预警 |
| 超出 30–50% | S2 |
| 超出 50–100% | S1 |
| 超出 >100% | S0 |

（3）花费不足

| 实际花费较近 7 天平均花费下降幅度（连续 ≥3 天） | 异常严重度 |
| --- | --- |
| 下降 <30% | 不预警 |
| 下降 30–50% | S2 |
| 下降 >50% | S1 |

（4）销量异常 / 销量增长提示（基准：过去 7 天日均销量）

下降方向：

| 当前销量 / 近 7 天日均（连续 ≥3 天） | 异常严重度 |
| --- | --- |
| 70%–100%（降幅 <30%） | 不预警（正常波动） |
| 50%–70% | S2 |
| 30%–50% | S1 |
| <30% | S0 |

上升方向（销量增长提示，封顶 S1）：

| 当前销量 / 近 7 天日均（连续 ≥3 天） | 异常严重度 |
| --- | --- |
| 100%–150%（涨幅 <50%） | 不预警 |
| 150%–200% | S2 |
| >200% | S1 |

判定说明：近 7 天平均 ACOS / 平均花费由系统按该产品过去 7 天历史数据计算并随标签抓取，本系统直接使用；不依赖人工设定的目标值。

严重度不对称：花费超出是直接花费损失，最高可达 S0；花费不足主要是机会成本，默认封顶 S1。销量同理——下降是损失型可达 S0，上升方向输出为”销量增长提示”，属于机会提示型封顶 S1。

原”广告消耗断量”场景暂不纳入判定。清货阶段产品（liquidating）的广告调整 AI 仅可建议、必须人工确认，对应方案”必须人工介入”属性。

### 3.7 目标偏离专项判定（基准：ERP 运营设定的日均目标单量 / 月目标）

目标偏离衡量”实际单量是否达到运营设定目标”，与销量异常（和自身近 7 天比”变化”）相互独立、互为补充：一个产品可能销量稳定却长期不达标（销量异常不报、目标偏离报）。采用三窗口判定：

| 时间窗口 | 比什么 | 基准 | 作用 |
| --- | --- | --- | --- |
| 当日 | 当日单量 vs 日均目标 | 日均目标单量 | 发现即时偏离，仅观察，不预警 |
| 近 3 天 | 近 3 天日均 vs 日均目标 | 日均目标单量 | 连续偏离才判定为异常 |
| 近 7 天 | 近 7 天日均 + 月累计完成率 vs 月目标节奏 | 日均目标 + 月目标 | 判断趋势性偏离、是否影响月目标达成 |

严重度分档（与销量异常档对齐；近 3 天连续偏离才进入分档）：

| 实际 / 日均目标（近 3 天连续） | 异常严重度 |
| --- | --- |
| ≥70%（差 <30%） | 不预警（正常波动） |
| 50%–70% | S2 |
| 30%–50% | S1 |
| <30%，或近 7 天持续偏离（近 7 天内逐日实际单量均低于日均目标，连续 7 天），或月累计完成率 / 月时间进度 <50% | S0 |

说明：仅当日偏离、近 3 天未连续的，不处理（不预警）。目标单量由 ERP 运营设定并抓取，本系统直接使用。月累计完成率 / 月时间进度 <50% 为”月目标严重落后”的初始判断口径，可在影子期 / 运营反馈后校准。

### 3.8 自然流量异常专项判定（基准：近 7 天平均自然订单占比）

自然订单占比 = 自然订单 / 总订单。占比下降反映自然流量健康度走弱；即使总销量被广告补足、看似稳定，自然这条腿仍可能在恶化。采用三窗口判定：

| 时间窗口 | 看什么 | 作用 |
| --- | --- | --- |
| 当日 | 当日自然订单占比 vs 近 7 天平均 | 即时下滑，仅观察，不预警 |
| 近 3 天 | 近 3 天平均占比连续低于近 7 天平均 | 连续偏离才判定为异常 |
| 近 7 天 | 近 7 天占比走势是否持续下行 | 判断趋势、确认慢性恶化，升级严重度 |

被动下降边界：若自然订单数未下降，只是总订单上涨导致自然占比被动下降，不直接按”自然单下滑型”处理；应进入模块 6.0.8 的”自然 vs 广告关系”查证，区分是否属于”增长依赖广告，自然没跟上”，或自然单也同步增长、只是广告增长更快导致占比下降。

严重度分档（自然占比下降幅度，vs 近 7 天平均，连续 ≥3 天）：

| 自然占比下降幅度 | 异常严重度 |
| --- | --- |
| <10 个百分点 | 不预警（正常波动） |
| 10–20 个百分点 | S2 |
| 20–35 个百分点 | S1 |
| >35 个百分点，或近 7 天持续下行（近 7 天内逐日自然占比均低于近 7 天平均基线，连续 7 天） | S0 |

注：档位数值为初值，可在影子期 / 运营反馈后直接调整。自然流量异常与销量异常相互独立——销量看总单量变化，自然流量看自然占比；它也是”目标偏离”原因查证中”流量减少”项所指向的异常。

### 3.9 卡位异常专项判定（基准：近 7 天平均卡位）

卡位 = 本产品在直接竞品集合中的排位（ERP 抓取，整数名次，数字越小越靠前）。当前卡位名次高于近 7 天平均卡位名次，即表示卡位下滑；卡位下滑 = 卡位名次数字变大，被竞品超过。下滑比例 =（当前卡位 − 近 7 天平均卡位）/ 近 7 天平均卡位；卡位为整数，下滑比例由当前整数卡位直接计算（如近 7 天均 5、当前 6 → 下滑 20%）。采用三窗口判定：

| 时间窗口 | 看什么 | 作用 |
| --- | --- | --- |
| 当日 | 当日卡位名次是否高于近 7 天平均卡位名次 | 即时下滑，仅观察，不预警 |
| 近 3 天 | 近 3 天平均卡位名次是否连续高于近 7 天平均卡位名次 | 连续下滑才判定为异常 |
| 近 7 天 | 近 7 天卡位名次是否持续变大 / 走势变差 | 判断趋势，升级严重度 |

严重度分档（卡位下滑比例，vs 近 7 天平均，连续 ≥3 天）：

| 卡位下滑比例 | 异常严重度 |
| --- | --- |
| <20% | 不预警（正常波动） |
| 20%–50% | S2 |
| 50%–100% | S1 |
| >100%，或近 7 天持续下行（近 7 天内逐日卡位名次均高于近 7 天平均基线，连续 7 天） | S0 |

注：档位数值为初值，可在影子期 / 运营反馈后直接调整。卡位异常是竞争入口层的上游信号，可能进一步导致自然流量异常、销量下滑，也是目标偏离 / 销量异常原因查证中可能指向的上游原因。

### 3.10 链接转化率异常专项判定（周维度，双基准）

口径：链接转化率 = 整条链接（父 ASIN）的订单商品总数 / 会话，链接级，不分变体。一周抓一次，周维度判定，不用三窗口。双基准任一触发即报，严重度取两者较高。已去掉原”由绿变红”判定。

空值不判定规则：若链接转化率字段为空、未生成、无法计算，或新品前期因数据未积累导致近 7 天 / 本周 / 上周转化率为空，则不触发链接转化率异常，也不进入 S0 / S1 / S2 分级；仅标记为”转化率数据为空 / 待数据积累”，不生成正式异常任务。注意：转化率为空不等于转化率为 0；若已有会话数据且系统计算出的转化率为 0，则属于有效数值，应继续按样本量门槛和双基准规则判定。

最低样本量规则：链接转化率异常需满足最低样本量后才输出正式异常。默认最低样本量：本周会话 ≥100；若用于本周 vs 上周比较，则本周和上周均需有有效会话数据。本规则中的”会话”对应业务报告中的会话字段，不使用”页面流量”作为转化率样本量基准。若本周会话 <100，但本周 + 上周订单商品总数 ≥10，可进入观察判断；若转化率下降明显，仅输出”转化率样本不足观察”，不进入正式 S0 / S1 / S2 分级。

基准 A：本周 vs 上周（自身变化）

| 本周转化率较上周降幅 | 异常严重度 |
| --- | --- |
| <20% | 不预警（正常波动） |
| 20%–50% | S2 |
| 50%–80% | S1 |
| >80% | S0 |

基准 B：本周 vs 类目平均转化率（是否低于同类）

| 本周转化率 / 类目平均转化率 | 异常严重度 |
| --- | --- |
| ≥80% | 不预警（接近同类水平） |
| 50%–80% | S2 |
| 30%–50% | S1 |
| <30% | S0 |

注：两个基准各算一个严重度，取较高者为最终严重度。档位数值为初值，可在影子期 / 运营反馈后直接调整。类目平均转化率由 ERP 直接提供；若字段缺失，按 3.4 全局字段缺失规则处理。

### 3.11 售后异常专项判定（评分 / 退款，双基准）

本节仅对评分异常、退款异常进行专项分级。近期集中差评不进入本节评分 / 退款专项分级；其触发口径见模块 2.7，默认严重度见 3.3。

评分异常（每日抓取，慢变量、不用三窗口；双基准任一触发即报、严重度取高）

评分异常空值规则：若当前评分为空、未生成，或新品前期尚未积累有效评分数据，则不触发评分异常，不进入 S0 / S1 / S2 分级；仅标记为”评分数据为空 / 待数据积累”。若当前评分已经生成，则无论评分数量多少，均可进入评分异常判定。新品早期评分数量少时，不作为降级或不判定理由，应在任务卡中标注”评分样本少，需重点读取评论内容确认产品质量问题”。

基准 A：当前评分 vs 近 7 天平均评分（评分下降幅度）

| 评分较近 7 天平均下降 | 异常严重度 |
| --- | --- |
| <0.1 分 | 不预警 |
| 0.1–0.3 分 | S2 |
| 0.3–0.5 分 | S1 |
| >0.5 分 | S0 |

基准 B：当前评分 vs 目标评分

| 评分相对目标评分 | 异常严重度 |
| --- | --- |
| ≥目标（达标） | 不预警 |
| 低于目标（含从达标跌破目标线） | S1 |

退款异常（一周抓一次、周维度，不用三窗口；双基准任一触发即报、严重度取高）

退款异常数据完整性规则：退款异常必须在本周与上周均存在正常退款率数据的情况下，才进行”本周 vs 上周”的环比判定。若上周退款率为空、未生成、无正常数据，或上周订单数据缺失，则不触发退款异常环比判定，不进入 S0 / S1 / S2 分级；仅标记为”退款数据不足 / 待补充”。

退款异常样本量规则：退款异常需满足最低订单样本量后才输出正式异常。默认最低样本量：本周订单商品总数 ≥20，或本周 + 上周订单商品总数 ≥30。若订单样本不足但退款率升高，仅输出”退款样本不足观察”，不进入正式 S0 / S1 / S2 分级。

基准 A：本周退款率 vs 上周（相对上升幅度）

| 本周退款率较上周相对上升 | 异常严重度 |
| --- | --- |
| <30% | 不预警 |
| 30%–60% | S2 |
| 60%–100% | S1 |
| >100% | S0 |

基准 B：本周退款率 vs 类目平均退换货率（倍数）

| 本周退款率 / 类目平均退换货率 | 异常严重度 |
| --- | --- |
| ≤1.2 倍 | 不预警 |
| 1.2–1.5 倍 | S2 |
| 1.5–2 倍 | S1 |
| >2 倍 | S0 |

注：各档数值为初值，可在影子期 / 运营反馈后直接调整。评分目标值、类目平均退换货率均由 ERP 提供；若字段缺失，统一按 3.4 全局字段缺失规则处理。

### 3.12 放量未执行专项判定（该做没做型，无需查证）

放量未执行 = 产品已满足全部放量条件、但广告未加投入（该放大却没放大）。与目标偏离形成闭环：未达标→目标偏离（查因修复）；达标且可放量却没放→放量未执行（提示放大）。下列 5 个条件全部满足即触发，默认严重度 S1。

销量增长提示是”销量正在上升”的前置信号，不等于放量未执行。只有同时满足销量达标、库存充足、ACOS 健康、自然占比上涨且广告未放量时，才触发放量未执行。若销量增长提示与放量未执行同时命中，优先输出放量未执行，销量增长数据作为判断依据展示。

| # | 放量条件 | 判定口径 |
| --- | --- | --- |
| 1 | 销量达标 | 连续 7 天日均销量 ≥ 日均目标单量 |
| 2 | 库存充足 | 可售库存 ≥ 日均单量 × 1.2 × 30（支撑放量后 1 个月，增幅 20%） |
| 3 | ACOS 健康 | 连续 7 天日均 ACOS < 目标 ACOS；近 7 天 ACOS 为空、未生成或广告样本不足时，不得直接判定为 ACOS 健康 |
| 4 | 广告未放量 | 近 3 天日均广告花费 ≤ 近 7 天平均花费 × 1.1 |
| 5 | 自然占比上涨 | 近 7 天平均自然订单占比 > 前 7 天平均自然订单占比，且近 3 天平均自然订单占比不低于近 7 天平均自然订单占比 |

数据不足边界：ACOS 健康必须基于有效广告数据判断；若近 7 天 ACOS 为空、未生成或广告样本不足，则不得输出正式”放量未执行”，仅标记为”放量机会待评估 / ACOS 数据不足”。

严重度：默认 S1（机会损失型——产品各项健康、自然流量加速向上却未放大，机会损失值得尽快处理）。处理建议：提示运营评估放量（加预算 / 扩词 / 加大投放），抓住上升势头。该点位无需原因查证（条件满足本身即结论）。各阈值（1.2、30、×1.1 等）为初值，可在影子期 / 运营反馈后直接调整。

### 3.13 库存积压专项判定（第一道：提前预警，可售天数 A + 目标累计 B 交叉）

库存积压属现象即原因型（不查证，直接给处理建议）。两个指标各自分档，再交叉取综合严重度。

数据完整性要求：库存积压正式判定前必须具备可售库存、近 30 天日均销量、未来 2–4 个月目标累计。若缺少未来 2–4 个月目标累计，则不得仅凭可售天数输出正式库存积压 S0/S1/S2，只能输出”库存压力待确认 / 数据不足”。可售天数用于判断当前库存压力，未来目标累计用于判断库存是否能被未来目标消化，两者必须交叉使用。

可售天数口径：可售天数 = 可售库存 ÷ 近 30 天日均销量。若上架不足 30 天，则按已上架有效销售天数计算，并标注”样本期较短”。若新品上架时间较短，或有效销售天数不足 7 天，不输出正式库存积压异常，仅标记为”新品库存压力待观察”。

日均销量为 0 的处理：若近 30 天日均销量为 0，且产品不是新品观察期，同时存在可售库存，则可售天数按”>120 天”处理，A 档判为 S0；若产品仍处于新品观察期，则不直接输出正式库存积压，标记为”新品库存压力待观察”。

A：可售天数（可售库存 ÷ 近 30 天日均销量）

| 可售天数 | A 档 |
| --- | --- |
| <60 天 | 不预警 |
| 60–90 天 | S2 |
| 90–120 天 | S1 |
| >120 天 | S0 |

B：目标累计（可售库存 vs 未来 N 个月目标累计，目标已含淡旺季）

| 可售库存覆盖 | B 档 |
| --- | --- |
| ≤未来 2 个月目标（本月 + 下月） | 不预警 |
| 2–3 个月目标 | S2 |
| 3–4 个月目标 | S1 |
| >4 个月目标 | S0 |

综合严重度（A、B 交叉）：

| A 可售天数 | B 未来目标累计 | 综合处理 |
| --- | --- | --- |
| A、B 均不预警 | A、B 均不预警 | 不输出库存积压。 |
| A、B 均有预警 | A、B 均有预警 | 取较高严重度。 |
| A 有预警 | B 不预警 | A 档降一档后输出，并提示复核未来目标是否可靠。 |
| A 不预警 | B 有预警 | B 档降一档后输出，并提示复核淡旺季和目标是否合理。 |
| A 或 B 关键数据缺失 | 任一关键数据缺失 | 不输出正式 S0 / S1 / S2，输出”库存压力待确认 / 数据不足”。 |

降档规则：S0 → S1；S1 → S2；S2 → 观察，不输出正式库存积压。

注：A 天数档（60 / 90 / 120）、B 月数档均为初值，可在影子期 / 运营反馈后调整。处理建议见模块 6.2（按 S2/S1/S0 给不同力度）。本异常的巡检频次由巡检频次规则文件统一维护；复查以运营设置时间优先，未设置时按默认复查规则执行。

### 3.14 滞销异常专项判定

滞销异常属现象即原因型（不查证，直接给处理建议）。针对已产生超龄仓租、短期无法消化、损失达规模的产品。它与库存积压不同：滞销看超龄那部分库存是否卖得掉，库存积压看整体可售库存撑多久。一个产品可整体库存健康却有超龄老货滞销。

计算层级：滞销异常先在子 ASIN / 变体层识别超龄库存与消化周期，再归集到父 ASIN 任务卡。父 ASIN 维度用于汇总单月超龄仓租费用和输出任务卡；父卡严重度取命中子 ASIN 中最高严重度。不同颜色 / 尺码库存不能互相消化，命中子 ASIN 的滞销库存应使用该子 ASIN 自身销量计算消化周期。

数据完整性要求：滞销异常正式判定前必须具备超龄库存量 / 滞销库存量、命中子 ASIN 近 30 天日均销量、单月超龄仓租费用、FBA 库龄 / 超龄状态。若缺少超龄库存量、单月超龄仓租费用或超龄状态，则不得触发正式滞销异常；不能用普通可售库存、库存积压结果或可售天数替代滞销判断。

消化周期口径：滞销库存消化周期 = 命中子 ASIN 滞销库存量 ÷ 命中子 ASIN 近 30 天日均销量。若命中子 ASIN 近 30 天日均销量 = 0，且存在滞销库存，则消化周期按 >120 天处理；若近 30 天日均销量为空、未生成或缺失，则按数据不足处理，不输出正式 S0 / S1 / S2。

准入条件（3 个全部满足才进入）：

| 准入条件 | 判定口径 |
| --- | --- |
| ① 有滞销库存 | 存在收取超龄仓租的库存（子 ASIN 查、父 ASIN 汇总）。 |
| ② 1 个月消化不完 | 命中子 ASIN 滞销库存 ÷ 命中子 ASIN 近 30 天日均销量 >30 天。 |
| ③ 超龄费达规模 | 父 ASIN 汇总单月超龄仓租费用 > $20。 |

严重度分级（按消化周期，只产出 S；定位权重 T、阶段、淡旺季由模块 4 统一打分施加）：

| 滞销库存消化周期（命中子 ASIN 滞销库存 ÷ 命中子 ASIN 近 30 天日均销量） | 严重度 |
| --- | --- |
| >30 天且 ≤60 天 | S2 |
| >60 天且 ≤120 天 | S1 |
| >120 天，或近 30 天日均销量 = 0 | S0 |

滞销异常与库存积压的共现去重规则：两者为独立异常，看不同库存维度（滞销看超龄部分卖不卖得掉、库存积压看整体可售库存撑多久），各自独立判定。但大多数情况下滞销产品也会触发库存积压，故定共现去重规则：

| 触发情况 | 处理 |
| --- | --- |
| 同时触发滞销异常 + 库存积压 | 取滞销异常作为主任务；库存积压不重复生成主任务、不重复计入打分，可作为关联库存压力在任务卡中展示。 |
| 仅触发滞销异常（整体不积压） | 正常报滞销异常。 |
| 仅触发库存积压（无超龄滞销） | 正常报库存积压。 |

理由：同时出现时，滞销是更具体、已发生实际损失的状态，取滞销可避免对同一批问题库存重复处理；库存积压为预测型风险，在滞销已暴露实际损失时不重复生成主任务。注：准入门槛（$20、30 天）为初值可调，处理建议见模块 6.2。本异常的巡检频次由巡检频次规则文件统一维护；复查以运营设置时间优先，未设置时按默认复查规则执行。


## 模块 4　优先级计算参数（配置表）

方案第五部分统一执行分数模型读取的全部参数集中于此，便于调参。修改本模块后 Agent 下次巡检即按新值计算。所有数值为初始建议值，需数据回流后校准。

### 4.0 执行分数公式（与方案第五部分一致）

单异常执行分数 = 异常基础分 × 定位系数 × 阶段系数 × 淡旺季系数

产品执行分数 = 最高单异常执行分数 + Σ(其余各异常执行分数 × 并发权重)

最终：按产品执行分数全局排序 → 按阈值映射执行优先级 P0/P1/P2

只有已经输出正式 S0 / S1 / S2 的异常，才进入模块 4 打分。数据不足、样本不足观察、转化率样本不足观察、新品库存压力待观察、放量机会待评估等观察类结果，不进入执行优先级打分。

打分只决定异常的初始执行优先级。超期不进打分——它由模块 5 升降级规则直接硬跳档（P1 满 7 天未处理→P0、P2 满 14 天未处理→P1），保证”拖太久必定升档”的确定性，而非靠加分。并发仍由打分体现（异常越多、产品执行分数越高，自然升档）。

### 4.1 异常基础分（严重度 × 变体重要性二维表）

基础分由异常严重度（S0/S1/S2）与异常作用层级 / 命中变体的重要性共同决定：链接级异常取”链接级异常基础分”列；变体级异常（含链接不可售、FBA 可售库存为 0、库存不足）按命中变体的主要色/次要色/长尾色取列。变体重要性已预乘进基础分，不再单列系数。

| 严重度 | 链接级异常基础分 | 变体级·主要色 | 变体级·次要色 | 变体级·长尾色 |
| --- | --- | --- | --- | --- |
| S0 | 100 | 100 | 70 | 25 |
| S1 | 60 | 60 | 42 | 15 |
| S2 | 30 | 30 | 21 | 8 |

取值规则：

- 链接级异常：发生在父体 / Listing 整体上的异常，取”链接级异常基础分”列；具体点位清单见模块 2.0，本节不重复罗列。

- 变体级异常：命中具体子体 / 变体的异常，按命中变体的重要性（主要色 / 次要色 / 长尾色）取列；具体点位清单见模块 2.0。

- 库存类异常（FBA 可售库存为 0、库存不足）：在子体层识别、命中对象记录到具体子 ASIN，按命中子体的变体重要性取列（主要色 / 次要色 / 长尾色）。

- 异常属于链接级还是变体级，见模块 2.0 归类清单；实际命中对象与默认归类不一致时，以模块 2.0 的通用规则为准（合规异常固定子体级，不适用兜底）。

- 次要色、长尾色基础分已按配置表预设，Agent 直接读取表内数值，不再二次计算。

### 4.8 完整算例（串联模块 1–4）

某 T1 重点产品、收割期、旺季前期，同时存在两个异常：

- 异常 A：黑色/M 码 FBA 可售库存为 0（变体级·库存类，命中主要色）→ 严重度 S0，基础分取 S0×主要色 = 100。

- 异常 B：灰色/XL 图片异常（变体级，长尾色）→ 严重度 S1，基础分取 S1×长尾色 = 15。

公共系数：定位 1.2 × 阶段 1.3 × 淡旺季 1.2 = 1.872。

单异常执行分数：

- A = 100 × 1.872 = 187.2

- B = 15 × 1.872 = 28.08

产品执行分数（最高分主导 + 其余 × 0.2 并发权重）：

187.2 + 28.08 × 0.2 = 187.2 + 5.62 = 192.82

192.82 ≥ 90 → 执行优先级 P0（当天处理）。

说明：主要色断货（A）主导了整张卡的执行分数与排序——黑色/M 为主要色，取 S0×主要色 = 100；长尾色图片异常（B）因变体重要性低、基础分仅 15，对结果影响很小但仍记录在卡内。任务卡归集到该父 ASIN，卡内列 A、B 两条子体明细 + 各自变体重要性 + 各自严重度；父卡严重度取子体最高 = S0。

本算例默认异常已通过模块 3 判定为正式 S0 / S1 异常；数据不足、样本不足观察、观察类提示不进入本算例打分。

### 4.9 分数相同时的破平规则（异常类型次序）

产品呈现顺序的第一排序键是产品执行分数（分数高的在前）。当两个产品的产品执行分数完全相同，或因系统展示/排序精度限制被视为相同分数时，用异常类型次序作为第二排序键破平：异常类型次序号小的（靠前的）先呈现。规则不改分数、不加分、不改变 P0/P1/P2 优先级，仅决定同分时谁先呈现。一个产品有多个异常时，取其最靠前（次序号最小）的异常参与破平。分数存在可区分差异时，仍按产品执行分数排序，本规则不介入。

破平规则只作用于已进入正式打分的主任务异常；数据不足、样本不足观察、观察类提示、关联现象、被共因去重后不作为主任务输出的异常，不参与破平。

触发边界：本规则仅在产品执行分数完全相同，或分数差小于系统展示/排序精度时启用。例如系统仅展示整数分时，92.1 与 92.4 可视为同分；若系统保留两位小数，则只有完全相同或差值低于 0.01 的情况才视为同分。具体精度由实现侧配置，但不得扩大到正常分数差异。

禁止项：破平规则不得提前参与异常基础分、单异常执行分数、产品执行分数或 P0/P1/P2 阈值映射；不得因为异常类型次序靠前而加分、升档或覆盖产品执行分数排序。

示例：产品 A、B 分数都是 92。A 的异常类型为次序 1（完全不能卖），B 为次序 3（合规高风险）→ A 次序号更小 → A 先呈现。

本表为同分破平排序表，不改变异常大类归属。评分异常仍归属模块 2.7 售后异常，但因评分下降对买家信任和转化影响更直接，破平次序上高于近期集中差评和退款异常。

异常类型次序表：

| 次序 | 异常类型 | 包含点位 |
| --- | --- | --- |
| 1 | 完全不能卖 | 链接不可售、FBA 可售库存为 0 |
| 2 | 卖得受阻 / 高断货风险 | Buy Box 丢失、变体掉线、父子体关系异常、库存不足 |
| 3 | 合规高风险 | 合规异常 |
| 4 | 已发生实际损失 | 滞销异常 |
| 5 | 交易表现 / 信任损失 | 销量异常（下降）、链接转化率异常下降、ACOS 异常、广告花费异常、目标偏离、自然流量异常、卡位异常、评分异常 |
| 6 | 库存积压 | 库存积压 |
| 7 | 内容 | 主图异常、标题异常、五点异常、图片异常、A+ 异常 |

## 模块 5　升降级与解除规则

打分（模块 4）决定异常的初始执行优先级（P0/P1/P2）。本模块定义初始优先级之后的事后调整——什么情况升档、降档、解除。升降级与打分分工：异常多/严重靠打分自然体现，超期/人工干预靠本模块规则。

本模块只作用于已经生成正式 P0 / P1 / P2 的异常任务；数据不足、样本不足观察、转化率样本不足观察、新品库存压力待观察、放量机会待评估等观察类结果，不进入升降级与解除流程。

### 5.0 总则

- 升级：在打分结果之上，因打分覆盖不到的因素（超期、人工高风险）强制升档。

- 降级：仅允许人工直接降级，且必须填写原因（唯一例外：模块 3.3.1 共因回落的系统自动降级，见 5.2）。

- 解除：异常关闭、移出处理队列（人工确认或自动恢复）。

- 恶化不单列规则：数据恶化导致更严重，是打分的默认行为（数据变重 → 分数升 → 自然到更高档），不需要单独的升级规则。波及面达到模块 3.3.1 共因上调条件（3 个及以上表现型异常共因），属于”数据恶化导致更严重”的一种具体体现，同属本条默认行为范畴，不属于模块 5.1 的硬跳档升级，不需要人工标记或额外审批。

- 并发不单列规则：同链接多异常已由打分体现（异常越多产品执行分数越高，自然升档），不设硬跳档。

### 5.1 升级规则（硬跳档）

| 当前等级 | 升级条件 | 升级后 | 要求 |
| --- | --- | --- | --- |
| P1 | 满 7 天未处理 | P0 | 硬跳档 |
| P2 | 满 14 天未处理 | P1 | 硬跳档 |
| 任意等级 | 运营人工标记高风险 | 仅允许升档至 P0 / P1 | 必须填写高风险原因 |

超期升级是硬跳档（满时间必定升档），不靠加分——保证”拖太久必定升级”的确定性。超期时长按执行优先级计（P1 的 7 天、P2 的 14 天）。

超期升级只判断是否”未处理”，不判断是否”未关闭”。若运营已完成初次处理或给出处理判断，但异常尚待复查 / 尚未关闭，不因”未关闭”触发超期升级。

运营人工标记高风险时，只允许升档至 P0 / P1，并必须填写高风险原因；不得通过”标记高风险”进行降级，降级统一走 5.2。

### 5.2 降级规则

| 降级方式 | 条件 | 要求 |
| --- | --- | --- |
| 人工直接降级 | 运营判断当前等级偏高（如已知可接受、有意为之、误判等） | 必填降级原因，记入处理记录 |
| 系统自动降级（仅限共因回落） | 该异常此前经模块 3.3.1 共因上调，本轮复扫共因数量降至阈值（3 个）以下 | 无需人工填写原因，须记录变更前后档位与触发 / 回落依据 |

降级分两种方式：人工直接降级，和系统自动降级（仅限模块 3.3.1 共因上调回落场景）。人工直接降级须写明原因，便于追溯。系统自动降级仅适用于以下情形：该异常此前经模块 3.3.1 共因上调规则提升过严重度，且本轮复扫共因数量降至规则阈值（3 个）以下——此时系统自动将严重度回落至初判档位，无需人工填写原因，但须记录变更前后档位与触发 / 回落依据。除此共因回落场景外，其余任何异常一律不适用系统自动降级，仍须人工直接降级。人工降级优先：若该异常此前已被运营人工直接降级，共因回落不直接覆盖人工判断，当前展示等级仍维持人工降级结果；系统仅在任务卡中提示”该异常共因已回落，当前维持人工降级，建议复核”，由运营决定是否撤销降级。

降级只改变当前执行优先级，不关闭异常；异常是否关闭仍按 5.3 解除规则执行。人工降级后，若后续复扫发现异常仍然严重，但系统识别到该产品该异常已被人工降级，则继续按人工降级后的等级执行，不立即覆盖人工判断。若连续超过 7 次复扫仍发现该异常保持严重状态，系统可按最新数据重新计算执行优先级，并提示运营复核是否继续维持人工降级。

### 5.3 解除规则（异常关闭）

| 解除方式 | 条件 | 要求 |
| --- | --- | --- |
| 人工确认已处理并关闭 | 运营确认已完成处理，且无需继续跟进 | 填处理动作 |
| 人工确认误报 | 核实为误报 | 填误报原因，记入误报样本（供校准） |
| 人工确认不需处理 | 运营判断无需处理 | 必填原因 |
| 自动恢复关闭 | Agent 复扫或下一判定周期发现问题已不存在 | 按异常类型执行自动恢复关闭规则，系统自动关闭并留记录备查 |

解除即异常关闭、移出队列。前三种为人工确认，第四种为系统自动（问题不存在了即自动关闭，但需按下表区分异常类型）。

| 异常类型 | 自动恢复关闭规则 |
| --- | --- |
| 现象即原因型异常 | 复扫发现问题已不存在，可自动关闭并留记录。库存类异常的复查以运营设置时间优先，未设置时按默认复查规则复扫（复扫的巡检节奏由巡检频次规则文件维护）。 |
| 日维度 / 连续窗口表现型异常 | 对 ACOS、广告花费、销量、目标偏离、自然流量、卡位等连续窗口类异常，需连续 3 天不再满足异常条件后，才自动恢复关闭。 |
| 周维度异常 | 链接转化率异常、退款异常等按周维度判定的异常，以下一次周维度判定结果为准；下一次判定不再满足异常条件，才可自动恢复关闭（复扫的巡检节奏由巡检频次规则文件维护）。 |
| 评分异常 | 评分回升至不再满足评分异常条件后，才可自动恢复关闭。 |

### 5.4 与打分、记忆的边界

- 升降级作用于已打分的异常，是打分之后的事后调整，不改打分公式本身。

- 升降级与解除规则不改变异常严重度 S，也不改变模块 4 的原始执行分数；它只改变任务当前展示等级或当前状态。

- 人工降级/解除改变的是该异常的当前状态，不影响其它异常的打分。

- 等级变更的历史追踪与变更提示（如”这条从 P2 变成了 P1，要提示运营”）依赖记忆系统（跨时间对比状态），属状态跟踪范畴，归方案文档/记忆系统处理，不在本知识库。

- 例外：共因回落（模块 3.3.1 共因上调规则触发的系统自动降级）不适用本条第 2 款”不改变异常严重度 S、不改变模块 4 原始执行分数”的限制——回落时严重度 S、模块 4.1 基础分与产品执行分数均按回落后的新档位重新计算。此为唯一例外，因共因回落本质是严重度的重判，仅在执行方式上归入模块 5.2 的系统自动降级流程管理；其余任何升降级仍严格遵守第 2 款，不改变严重度与原始分数。


## 模块 6　异常处理建议（处理建议库）

Agent 判定出异常点位与严重度后，按本库取对应处理建议，填入任务卡「处理建议」字段（模块 7）。运营每次只看到命中的那一条，不是整张表。

建议风格：大方向排查指引（查什么、做什么），非精确操作步骤。来源为业务方处理建议表，已按本库术语（严重度 S0/S1/S2）整理。

### 6.0 表现型异常原因查证

模块 6 输出路径总则：表现型异常统一按 6.0 对应小节完成查因、路由和输出；非表现型异常及具体异常点位不进入 6.0 查因，直接按 6.2 对应点位输出。若非表现型异常的大类已识别，但具体异常点位未命中 6.2 建议表，则按 6.3 大类兜底输出，并保留原具体异常点位，不得只输出大类名称。

适用范围：本节仅适用于已经通过模块 3 判定并输出正式 S0 / S1 / S2 的表现型异常。数据不足、样本不足观察、转化率样本不足观察、观察类提示、新品无广告无可售库存场景下被豁免的经营表现项，不进入本节原因查证。现象即原因型异常跳过本节，直接走处理建议。本节按大类绑定：2.5、2.7 新增的表现型点位，需在此同步补充对应的原因查证表。

为什么要查证：表现型异常（如转化率下降、ACOS 异常、销量异常）的现象不等于原因，背后有多个可能原因。直接把所有可能原因甩给运营，等于让运营自己排查。本节由 Agent 先逐个验证可能原因，只输出验证成立的异常明细、原因说明和对应处理建议。已通过模块 3 判定为正式 S0 / S1 / S2 的异常，均需在任务卡中作为异常明细展示，不得因后续查到真实原因而删除或隐藏；查证出的真实原因用于解释异常原因，并路由至对应具体点位的处理建议。

查证流程：1）取该表现型异常的”可能原因清单”；2）对每个原因按”验证方式”调用数据/skill 检查；3）判断是否满足”成立条件”；4）将所有正式命中的异常保留为异常明细，只把验证成立的原因带入对应输出；全部不成立时标注”未定位到明确原因，建议人工排查”。每个表现型异常小节只保留一个最终兜底输出；表格分支未命中时，进入本小节兜底，不在每一行重复生成兜底话术。若同一真实原因解释多个表现型异常，则按 6.0.1 共因去重规则生成主任务，避免重复生成任务和重复计入打分；但被去重的异常仍需作为异常明细、关联现象或判断依据展示。

输出粒度规则：本模块中表格出现”指向某类待办”“路由至某类异常”“输出某类处理建议”等表述时，仅表示 Agent 需要进入该异常大类下匹配实际命中的具体点位，不代表最终任务卡只输出异常大类名称。Agent 最终输出必须包含两部分：第一，实际命中的具体异常点位；第二，该点位在对应处理建议表中的具体待办 / 处理建议。不得只输出异常大类，也不得只输出命中点位而不输出对应待办。

内部查证动作外显边界：本节中的”验证方式 / 成立条件”属于 Agent 内部查证动作，最终任务卡不直接输出内部查证步骤，只输出查证成立后的异常明细、原因说明、具体异常点位和对应待办。

库存类查证条件统一口径：本节各查证表中涉及库存类异常（FBA 可售库存为 0、库存不足）的并发查证条件，按”命中次要色 / 长尾色变体（未波及主要色）“判断——此时主要色仍正常成交、链接整体仍可展示，库存问题作为并发原因参与查因。若库存类异常命中主要色，则该链接按模块 2.0.1 跳过表现型巡检，不会进入本节查证。

#### 6.0.1 多表现型异常共因去重规则

多个表现型异常可能由同一个真实原因触发。为避免任务卡重复轰炸，Agent 在完成原因查证后，必须先判断是否存在”共因”：多个表现型异常是否共同指向同一个现象即原因型异常、同一个外部市场原因，或同一个明确运营动作缺口。

| 共因类型 | 典型情况 | 输出规则 | 任务卡呈现 |
| --- | --- | --- | --- |
| 指向同一个现象即原因型异常 | 某核心成交子体 FBA 可售库存为 0，同时导致销量下降、目标偏离、自然流量异常、广告花费异常 · 花费不足 | 只输出该现象即原因型异常作为主任务；表现型异常不重复生成主任务 | 主任务写库存异常；关联现象写销量下降、目标偏离、自然流量下降、广告花费异常 · 花费不足 |
| 指向同一个外部原因 | 主要竞品降价同时导致转化率下降、卡位下滑、销量下降 | 合并为一个外部原因评估项，不拆成多条重复建议 | 任务卡写”竞品降价影响转化与卡位”，列相关数据 |
| 指向同一个动作缺口 | 销量增长提示与放量未执行同时命中 | 输出”放量未执行”作为主任务；销量增长提示作为异常明细 / 判断依据展示，不单独生成任务，也不重复计入打分 | 主任务写放量未执行；异常明细 / 判断依据列销量连续增长数据 |
| 原因不同 | ACOS 异常由广告投放低效导致，同时售后异常由差评集中导致 | 分别输出，各自保留处理建议 | 任务卡内按执行分数排序展示多条异常明细 |

去重边界：共因去重不改变模块 3 的原始异常识别结果；但在任务卡输出、产品执行分数聚合、并发加成和破平排序时，以去重后的主任务为准。被去重的表现型异常必须保留为”异常明细 / 关联现象 / 判断依据”，用于解释主任务为什么紧急，但不重复生成主任务、不重复计入打分、不参与并发加成和破平。

| 市场需求下降 | 查直接竞品的大类排名走势 | 直接竞品大类排名普遍同步下滑（非本品独有） | 监测到直接竞品大类排名普遍下滑，疑似市场需求整体下降；请评估 |

外部原因处理边界：若销量异常主要由竞品降价、竞品活动增强、竞品排名上升、市场新增竞品、季节性需求下降或类目流量整体下降导致，则标记为”外部原因 / 竞争环境变化提示”。该类原因不作为可直接修复异常输出，但需作为销量异常的原因说明，并提示运营评估价格、促销、广告、防守词、Listing 承接和库存策略是否需要调整。

**兜底（以上内外原因均不成立时）：**

| 可能原因 | 验证方式 | 成立条件 | 成立后输出 |
| --- | --- | --- | --- |
| 销量下降原因待人工评估 | 内外原因排查后均未命中 | 内部原因、外部原因均不成立 | 经查无明确内部异常、竞品市场无明显变化，销量下降原因待人工综合评估 |

输出（嵌入父卡，作为本条明细展开）：销量异常作为父卡里的一条异常明细，必须保留展示。其”原因/建议”栏展开为查证结果，不重复父卡已有的产品信息、负责人、优先级。只输出成立的原因：内部成立项→“需修复”区（☐，指向对应已有待办）；外部成立项→“需评估”区（◇，带查到的实际数据，标记为外部原因 / 竞争环境变化提示）；底部列”已排除”项。若查到明确内部真实原因，则该原因作为销量异常的原因说明并路由至对应点位处理建议；销量异常仍作为异常明细展示。内外全部不成立→按兜底输出人工评估提示。

#### 6.0.3.1 销量增长提示（销量异常上升方向）—— 排查后输出

销量增长提示是机会提示型（封顶 S1），不查病因（它不是问题），而是排查”机会条件”，只对排查成立的项给对应建议。排查层层递进：先判增长真不真 → 健不健康 → 要不要放量 / 能不能提价 / 货够不够。

| # | 排查项 | 验证方式 | 成立条件 | 成立后输出 |
| --- | --- | --- | --- | --- |
| 1 | 增长真实性/可持续性 | 查上升是否由促销/降价驱动、是否一次性大单或异常波动 | 增长非真实趋势（促销催 或 一次性大单/异常） | 本次上升疑似由{促销降价/一次性大单/异常波动}驱动，非趋势性增长，建议谨慎观察，不继续输出放量、提价、补货等机会建议 |
| 2 | 增长是否健康（自然驱动） | 查自然订单占比是否同步上升 | 自然占比同步上升 | 增长由自然流量驱动（自然占比 {X}%↑），增长较健康，可评估加大投入或承接流量 |
| 3 | 是否该放量 | 查 ACOS 是否健康（<目标ACOS）、广告花费是否未加投 | ACOS 健康 且 广告未加投 | ACOS 健康（{X}<目标）、广告未加投，建议评估放量（加预算/扩词）；详见放量未执行 |
| 4 | 价格试探（提利润） | 增长真实前提下，查本品到手价 vs 主要竞品到手价 | 增长真实 且 本品价格明显低于竞品（价格优势大） | 增长真实且本品价格显著低于竞品（本品 ${X}、竞品均价 ${Y}），有涨价空间，建议试探性涨价测试需求弹性、提升利润 |
| 5 | 库存能否支撑 | 查可售库存 vs 按上升后销量预估的消耗 | 库存撑不住上升后的销量（快断货） | 销量上升但库存不足，预计 {X} 天断货：① 建议尽快补货；② 若补货来不及，建议同步试探性涨价，放缓销售速度、延后断货时间，避免直接断货掉权重。 |

输出（嵌入父卡明细）：销量增长提示作为父卡里的一条异常明细，展开为排查结果——只列排查成立的项及对应建议，不重复父卡产品信息、优先级。若同时命中放量未执行，则本条不单独输出，销量增长数据写入放量未执行的判断依据。各项建议均为提示运营评估，不自动执行。注：涨价动作出现在两处，目的不同——第 4 项为价格优势大时主动涨价提利润；第 5 项为库存不足时涨价放缓消耗、保权重。

输出控制：若同轮巡检中该产品已正式命中库存与可售异常，则主任务按库存异常对应具体点位输出处理建议；销量增长提示中的库存风险仅作为背景说明或判断依据，不重复生成库存类任务。

#### 6.0.4 ACOS 异常

**第一层：拆广告漏斗（ACOS = CPC ÷（CVR × 客单价），四环全覆盖；查产品整体广告数据，不下钻单个广告活动）**

说明：CTR 不直接进入 ACOS 公式，但 CTR 下降通常反映广告流量相关性、主图吸引力、价格展示或竞争环境变化，因此作为 ACOS 异常的辅助查证信号。

| 环节 | 查什么指标 | 判断 | 输出 |
| --- | --- | --- | --- |
| 点击成本环 | CPC、各广告位花费分布、总花费 | CPC 较近 7 天上升，或花费集中在低效广告位 | 列数据：CPC ${X}→${Y}，广告位花费{分布}，总花费{Z}；点击成本上升，提示广告侧关注（不触发第二层） |
| 点击率环 | CTR、点击量 | CTR 较近 7 天下降 | 列数据 + 触发第二层深查 |
| 转化环 | CVR、广告订单数 | CVR 较近 7 天下降 | 列数据 + 触发第二层深查 |
| 客单价环 | 客单价/售价 | 客单价/售价较近 7 天下降（同样订单销售额变少→ACOS 被动升高） | 列数据：客单价 ${X}→${Y}；查是否并发价格与促销异常→命中则指向「价格与促销异常」对应待办；否则提示核查是否为运营主动降价/主动促销。若为主动降价/促销，不作为价格异常修复，建议运营同步下调广告 CPC/出价以匹配新客单价，避免 ACOS 持续偏高。 |

**第二层：CTR 或 CVR 任一下降时，查承接端为什么变差**

| 可能原因 | 验证方式 | 成立条件 | 成立后输出 |
| --- | --- | --- | --- |
| 评分/差评/高退换货风险变差 | 查评分、差评近期是否变化，是否命中退款异常或前台高退换货标签 | 命中售后异常（评分/差评/退款异常或高退换货标签） | 指向「售后异常」待办 |
| A+等内容异常 | 查是否并发内容完整性异常（缺失/不合格，含次要色/长尾色主图异常） | 命中内容完整性异常 | 指向「内容完整性异常」待办 |
| 内容改动（内容完整性异常未命中时的兜底） | 内容完整性异常未命中，提示核查是否改动过 listing | 内容完整性异常不成立 | 建议运营核查近期是否改动过 listing（主图/A+/标题等，可能改成了合格但效果差的内容） |
| 价格竞争优势下降 | 查本品+主要竞品近 7 天到手价 | 本品相对竞品变贵 | 监测到价格竞争优势下降：本品 ${X}→${Y}，竞品 ${Z}→${W}；请评估 |
| 非主要色链接状态异常 | 查是否并发链接状态异常（次要色/长尾色的链接不可售、Buy Box 丢失等） | 命中，作用于非主要色 / 部分子体 | 指向「链接状态」待办 |
| 部分变体掉线 / 部分子体库存异常 | 查是否并发变体掉线、库存不足，或次要色/长尾色的FBA 可售库存为 0 | 命中且作用于部分子体 | 指向「库存/变体异常」待办 |

**最终兜底（第二层各原因均不成立时）：**

| 可能原因 | 验证方式 | 成立条件 | 成立后输出 |
| --- | --- | --- | --- |
| 广告投放问题 | 第二层各承接原因排查后均未命中 | 评分、内容完整性异常、价格与促销异常、变体掉线均不成立 | 经查承接端无明确异常，疑似广告投放本身问题；列出广告漏斗数据，转广告 Agent / 运营处理 |

输出（嵌入父卡，作为本条明细展开）：ACOS 异常作为正式命中的表现型异常，必须作为异常明细保留展示。其”原因/建议”栏展开为查证结果，不重复父卡产品信息、负责人、优先级。第一层列出四环数据（CPC/CTR/CVR/客单价/花费/广告位/点击/订单），定位恶化环节；客单价下降→指向价格与促销异常或提示核查主动降价/促销，并提示同步降 CPC；CTR 或 CVR 恶化→展开第二层（内部→需修复☐、内容完整性异常未命中→提示核查 listing 改动、外部→需评估◇）；第二层均不成立→使用最终兜底输出，判定为疑似广告投放本身问题，列出广告漏斗数据，转广告 Agent / 运营处理。

#### 6.0.5 广告花费异常

广告花费异常 = 实际广告花费连续 ≥3 天偏离近 7 天平均花费（双向：花费超出 / 花费不足）。所有指标对比口径统一：近 3 天 vs 近 7 天均值（与判定标准一致）。

方向一：花费超出（实际广告花费高于正常）

不纠结具体成因（运营主动加/闲置组消耗等系统难查），直接看近 3 天 ACOS（对比目标 ACOS）判断是健康增长还是浪费。

基础输出（必出）：花费（近 3 天）从 ${X} 增加到 ${Y}（较近 7 天均值 +{Z}%），请运营排查是否正常情况（是否主动加投/流量变化等）

| ACOS情况 | 验证方式 | 成立条件 | 成立后输出 |
| --- | --- | --- | --- |
| ACOS 健康 | 查近 3 天 ACOS vs 目标 ACOS | 近 3 天 ACOS < 目标 ACOS | 广告花费异常 · 花费超出已触发，但近 3 天 ACOS 健康（近 3 天 {X}<目标 {Y}），暂判断为高效增长型花费上升；建议运营确认是否为主动加投，并关注自然流量承接和预算分配，判断是否需要将预算向高效流量倾斜。 |
| ACOS 不好 | 查近 3 天 ACOS vs 目标 ACOS | 近 3 天 ACOS ≥ 目标 ACOS | 花费增长且 ACOS 偏高（近 3 天 {X}≥目标 {Y}），存在花费浪费；若同时正式命中 ACOS 异常，则按 ACOS 异常对应查证结果和处理建议输出，广告花费异常 · 花费超出作为异常明细和关联现象保留。 |

方向二：广告花费异常 · 花费不足（实际广告花费低于正常）

花费不足多为机会损失，但也可能是效率提升或自然替代（好事）。用漏斗诊断：看花费下降时，曝光/点击/订单/广告单/自然单（均近 3 天 vs 近 7 天均值）怎么变，据此定位。

基础输出（必出）：花费（近 3 天）较近 7 天均值 -{Z}%，从 ${X} 降到 ${Y}，触发广告花费异常 · 花费不足

必出提示（系统查不到运营动作）：提示运营核查：本次花费下降是否为近期主动调低预算/出价所致；若是，属主动调整，确认即可

广告花费异常 · 花费不足输出原则：广告花费异常 · 花费不足属于表现型异常，表格中的”验证方式”是 Agent 内部查证动作，不作为最终话术原样输出。最终输出时，Agent 只输出已验证成立的原因和对应处理建议。若查证命中已有异常点位（如链接状态异常、库存与可售异常、内容完整性异常、价格与促销异常、售后异常等），则引用该异常点位在模块 6.2 中的对应处理建议；广告花费异常 · 花费不足作为异常明细和关联现象展示，不直接输出”提高出价 / 扩词”等广告侧动作。若未命中已有异常点位，再按广告漏斗或市场侧原因输出对应建议。

| 数据表现（近3天 vs 近7天） | 原因方向 | 验证方式 | 成立后输出 |
| --- | --- | --- | --- |
| 花费↓ 曝光↓ 点击↓ | 广告拿不到展示 | 查曝光、点击、CPC/出价 | 出价偏低/竞争致曝光不足，建议评估提高出价；另提示运营核查关键词覆盖是否不足/匹配过窄（系统无法查，可扩词/放宽匹配） |
| 花费↓ 曝光持平 CTR↓ | 买家不愿意点 | 查 CTR，并查是否并发内容完整性异常、价格与促销异常、售后异常 | CTR 下降、买家不愿点；查主图 / 价格 / 评分 / 售后风险 → 命中则指向「内容完整性异常 / 价格与促销异常 / 售后异常」对应待办 |
| 花费↓ 点击持平 订单持平 | 健康型花费下降 | 查点击量、订单是否持平 | 花更少钱拿到同样点击与订单，属于健康型花费下降，无需按负向异常处理；提醒关注后续花费是否持续走低影响放量空间，可考虑将节省预算用于扩量。 |
| 花费↓ 广告单↓ 总单持平（自然单上升补足） | 自然替代广告（健康型花费下降） | 查广告单↓但自然单是否上升、总单是否持平 | 广告单下降但自然单上升补足、总单稳定，属于自然替代广告的健康型花费下降；建议运营确认是否可顺势降低广告依赖，或将预算转向更高效流量。 |
| 花费↓ 广告单↓ 总单↓ | 已影响目标单量 | 查广告单、总单是否同步下降 | 广告花费异常 · 花费不足已拖累总单量、影响目标达成，需重视；关联「目标偏离」。 |
| 花费↓ 广告单↓ 自然单也↓ | 上游承接 / 市场 / 产品力问题 | ① 查是否并发链接状态异常（次要色/长尾色的链接不可售、Buy Box 丢失等）；② 查是否并发库存与可售异常，如次要色/长尾色的FBA 可售库存为 0 或库存不足；③ 再查直接竞品广告活跃度 / 市场需求是否同步下降；④ 以上均不成立时，提示核查产品力或 Listing 承接。 | 按命中分支输出，不得整段照搬；若本行分支原因均未命中，则进入 6.0.5 广告花费异常最终兜底，不在本行重复生成兜底话术。① 命中链接状态异常：输出对应链接状态点位及模块 6.2 处理建议，广告花费异常 · 花费不足作为关联现象展示。② 命中库存与可售异常：输出对应库存异常点位及模块 6.2 处理建议，广告花费异常 · 花费不足作为关联现象展示。③ 命中竞品广告活跃度下降或市场需求下降：输出市场流量整体变弱提示，建议观察或评估市场变化。④ 本行分支均未命中：进入 6.0.5 广告花费异常最终兜底。 |

兜底（以上数据表现均不匹配时）：花费下降但漏斗各环无明显匹配/在正常波动内，原因不明确；提示运营核查广告投放设置与近期调整

输出（嵌入父卡明细）：广告花费异常需作为任务卡异常明细展示，并按花费超出 / 花费不足方向展开。花费超出必出花费变化，并结合近 3 天 ACOS 判断是高效增长型花费上升还是花费浪费；花费不足必出花费变化、运营自查提示和漏斗诊断定位结果。验证方式仅作为 Agent 内部查证动作，最终话术只输出已验证成立的原因和对应处理建议；若命中已有异常点位，则调用对应点位处理建议，广告花费异常作为异常明细和关联现象展示。能查的给数据、查不到的提示运营核查；广告内部问题转广告 Agent / 运营处理。不重复父卡产品信息、优先级。

#### 6.0.6 目标偏离

核心逻辑：目标单量没完成，先拆”广告单 vs 自然单”定位问题在哪侧 → 自然侧/整体走漏斗（曝光/点击/转化）拆原因 → 结合价格/库存/评价/竞品判断 → 漏斗都正常则排查主动动作是否缺失。

**第零层：先拆 广告单 vs 自然单，定位问题在哪侧（主判定：近 7 天自然订单占比；阈值 30%/55% 为初值可调）**

| 现象 | 判定标准 | 含义 | 成立后输出 |
| --- | --- | --- | --- |
| 广告单有，自然单少 | 近 7 天自然占比 < 30% | 广告单量正常/不低，但自然占比低 → 广告在出单，自然没起来 | 转第一层漏斗拆（自然单为什么少），据漏斗定位给指向 |
| 自然单有，广告单少 | 近 7 天自然占比 > 55%（广告占比低） | 自然单量正常/不低，但广告单量很低 → 产品行，广告没放开 | 产品自然表现良好（自然单 {X}）、广告投入不足（广告单 {Y}），建议追加广告预算/扩大精准词投放（广告放量），见「放量未执行」 |
| 两者都少 | 总单量低于自身近 7 天均值，自然占比居中（30%–55%） | 自然单、广告单绝对量都低 → 总量不够 | 转第一层漏斗拆 |

**第一层：拆漏斗，定位缺口在哪一环（自然侧/整体走此层）**

| 环节 | 查什么指标 | 判断（对照诊断表） |
| --- | --- | --- |
| 流量环 | 曝光/访问量、自然占比、卡位 | 曝光低+点击低+单量低 = 流量入口不足 |
| 点击环 | 点击量/CTR | 曝光高+点击低+单量低 = 点击吸引力差 |
| 转化环 | 转化率 | 点击高+转化低+ACOS高 = 链接承接差 |
| 产品竞争力 | 本品vs竞品价格、卡位整体位置 | 各环都还行但整体打不过竞品 |

**第二层：针对定位的环，查具体原因**

流量不够（流量入口不足）→ 查：

| 可能原因 | 验证方式 | 成立条件 | 成立后输出 |
| --- | --- | --- | --- |
| 自然流量减少 | 查是否并发自然流量异常 | 命中自然流量异常 | 指向「自然流量异常」待办 |
| 卡位下滑 | 查是否并发卡位异常 | 命中卡位异常 | 指向「卡位异常」待办 |
| 广告投放收缩 | 查是否并发 ACOS/广告花费异常、广告曝光下降 | 命中广告类异常 | 指向已命中的 ACOS 异常、广告花费异常或放量未执行；若未命中具体异常点位，则转广告 Agent / 运营核查广告扩量、关键词覆盖等问题。 |

点击不够（点击吸引力差）→ 查：

| 可能原因 | 验证方式 | 成立条件 | 成立后输出 |
| --- | --- | --- | --- |
| 内容影响点击 | 查是否并发内容完整性异常（缺失/不合格，含次要色/长尾色主图异常） | 命中内容完整性异常 | 指向「内容完整性异常」待办；优化方向：标题、图片 |
| 内容改动 | 内容完整性异常未命中，提示核查是否改动过 listing | 内容完整性异常不成立 | 建议运营核查近期是否改动过 listing（主图/标题等） |
| 价格无竞争力影响点击 | 查本品vs竞品到手价 | 本品相对竞品变贵 | 监测到价格竞争优势下降：本品 ${X}→${Y}、竞品 ${Z}→${W}；优化方向：价格、coupon |
| 评分/差评影响点击 | 查是否并发售后异常 | 命中售后异常 | 指向「售后异常」待办 |

转化不够（链接承接差）→ 查：

| 可能原因 | 验证方式 | 成立条件 | 成立后输出 |
| --- | --- | --- | --- |
| 转化率下降 | 查是否并发链接转化率异常下降 | 命中链接转化率异常下降 | 指向「链接转化率异常下降」待办；优化方向：Listing、价格、评价、库存 |
| 非主要色链接状态异常 | 查是否并发链接状态异常（次要色/长尾色的链接不可售、Buy Box 丢失等） | 命中，作用于非主要色 / 部分子体 | 指向「链接状态」待办 |
| 部分变体掉线（断码断色） | 查是否并发变体掉线、库存不足，或次要色/长尾色的FBA 可售库存为 0 | 命中且作用于部分子体 | 指向「库存/变体异常」待办；优化方向：补货或降广告 |
| 新增差评致信任下降 | 查是否并发售后异常 | 命中售后异常 | 指向「售后异常」待办；优化方向：修文案、QA、图片说明 |

产品竞争力不够（各环都行但整体打不过）→ 查：

| 可能原因 | 验证方式 | 成立条件 | 成立后输出 |
| --- | --- | --- | --- |
| 价格竞争优势下降（变化型） | 查本品+竞品近 7 天到手价 | 本品相对竞品变贵（本品涨/竞品降） | 监测到价格竞争优势下降：本品 ${X}→${Y}、竞品 ${Z}→${W}；优化方向：降价或 coupon |
| 价格优势可能不足（静态，需运营判断） | 列出本品与主要竞品的价格数据、折扣幅度 | 自然转化不佳、无其他明确原因（提示项） | 列价格事实供运营判断：本品到手价 ${X}、主要竞品 {ASIN:$Y…}、本品相对竞品折扣 {N}%；请运营判断价格优势是否足够、是否需降价/加 coupon |
| 市场新增竞品 | 监测关键词/类目新增竞品 | 出现有销量占比的新竞品 | 监测到 {N} 个新竞品进入 {关键词}；请评估竞争策略 |
| 市场需求整体下降 | 查直接竞品大类排名走势 | 直接竞品大类排名普遍同步下滑（非本品独有） | 监测到直接竞品大类排名普遍下滑，疑似市场需求整体下降；请评估 |

**第三层：最终兜底 —— 前面各层都排查过、仍无明确指向时**

经第零层（广告单/自然单）、漏斗各环、产品竞争力均已排查，无异常、前面各层也无明确可优化动作，仍不达标 → 质疑目标本身。价格/广告放量/自然流量等主动动作建议已在第零层与第二层各环给出，此处不重复。

| 可能原因 | 验证方式 | 成立条件 | 成立后输出 |
| --- | --- | --- | --- |
| 目标合理性评估 | 对照该产品历史能力，判断是否已达自然瓶颈、目标是否定得过高 | 前面各层均无异常、无可优化动作，仍不达标 | 评估目标合理性：可能已达自然瓶颈或目标定得过高，建议校准目标；若仅短期轻微偏离则继续观察 |

输出（嵌入父卡明细）：作为父卡”目标偏离”明细展开，显示三窗口数据（当日/近3天/近7天实际 vs 目标、月累计完成率）。诊断顺序：第零层（广告单/自然单定位侧）→ 自然侧/整体走第一层漏斗定位、广告侧直接转放量 → 第二层具体原因（内部→需修复☐指向待办、外部→需评估◇带数据）→ 漏斗都正常则第三层目标校准。利润维度（订单有但利润差/成交结构）暂不纳入。不重复父卡产品信息、优先级。

#### 6.0.7 售后异常（差评 / 评分 / 退款）

售后异常为表现型：现象（差评数/评分/退款率）不等于原因。由 Agent 读取评论内容（差评/评分）或退款理由（退款）文字，归类出真实原因并给占比。差评与评分共用”读评论内容”查证，退款用”读退款理由”查证。

**评分异常 —— 两步处理（先处理评分，再分析优化方向）：**

第一步（必做，优先）：看到评分异常立即处理评分本身，不依赖原因分析。

| 动作 | 输出 |
| --- | --- |
| 评分维护（仅评分异常命中时必出） | 评分异常已影响买家信任与转化，优先处理评分：① 处理负面评分：通过拆分变体以及合理绑定变体解决；② 加强合规评价获取（Vine / Request a Review）；③ 持续监控评分回升 |

第二步：读差评/评论内容，定位具体该优化哪些（与差评共用下表）。

**差评 / 评分（第二步）—— Agent 读评论内容归类，定位优化方向：**

| 可能原因 | 验证方式 | 成立条件 | 成立后输出 |
| --- | --- | --- | --- |
| 尺码/版型问题 | 读差评/低星评论，统计尺码相关占比 | 尺码类占比突出 | 尺码问题占 {X}%，建议核对尺码表、修正页面尺码信息 |
| 质量问题 | 读评论，统计质量相关占比 | 质量类占比突出 | 质量问题占 {X}%，反馈产品/供应链/质检 |
| 物流/包装损坏 | 读评论，统计物流损坏相关占比 | 物流类占比突出 | 物流损坏占 {X}%，反馈仓储/包装 |
| 页面描述不符 | 读评论，统计”与描述不符”相关占比 | 描述不符类占比突出 | 描述不符占 {X}%，建议修复页面预期 |

退款 —— Agent 读退款理由归类：

| 可能原因 | 验证方式 | 成立条件 | 成立后输出 |
| --- | --- | --- | --- |
| 尺码/版型问题 | 读退款理由，统计尺码相关占比 | 尺码类占比突出 | 尺码问题占 {X}%，建议核对尺码表/页面 |
| 质量问题 | 读退款理由，统计质量相关占比 | 质量类占比突出 | 质量问题占 {X}%，反馈产品/供应链/质检 |
| 物流/包装损坏 | 读退款理由，统计物流相关占比 | 物流类占比突出 | 物流损坏占 {X}%，反馈仓储/包装 |
| 页面描述不符 | 读退款理由，统计描述不符相关占比 | 描述不符类占比突出 | 描述不符占 {X}%，建议修复页面预期 |

输出（嵌入父卡明细）：按原因占比从高到低列出主要原因，差评 / 评分异常读取评论内容；退款异常读取退款理由。指向对应处理（反馈供应链/质检/仓储/修页面）。Agent 文字归类置信度低或无明显主因时，提示”退款 / 差评 / 评分原因分散，建议人工复核评论或退款理由”。

#### 6.0.8 自然流量异常

前提：本查证针对已判定为自然流量异常的产品（自然占比较近 7 天下降、达判定阈值）。自然流量异常属”变化型”——只定位导致占比下降的变化原因，不含静态因素。查证只定位原因、给处理，不再判断是否异常。

**第一层：看”自然 vs 广告关系”，归类原因方向（近 3 天 vs 近 7 天）**

| 数据表现 | 原因方向 | 成立后输出 |
| --- | --- | --- |
| 自然单↓ 总单↓ | 真自然流量下滑 | → 进第二层查具体病因 |
| 自然单↓ 总单稳定 | 广告补住总单，自然腿变弱 | 总单被广告掩盖、自然在恶化（易被忽视）；→ 进第二层查病因 |
| 自然单稳定或上升，但自然单增幅低于总单增幅 | 增长依赖广告，自然没跟上 | 总单上涨但自然未同步增长，增长靠广告推动、自然权重没跟上，增长质量不健康；建议关注自然流量提升（核心词排名/SEO），让自然跟上增长 |
| 广告单↑ 总单不涨 | 广告替代自然单 | 广告单增但总单未涨，广告在替代本可免费获得的自然单。建议：① 削减无效替代的广告花费；② 将预算转投到能带动自然流量增长的广告活动上（核心词排名、精准广告），主动培育自然流量、追自然增长 |

**第二层：自然单真降，定位具体病因（用转化率分流：转化率未降→流量入口问题；转化率也降→承接问题）**

A. 自然单↓、转化率未降 → 自然流量入口减少（内部）：

| 可能原因 | 验证方式 | 成立条件 | 成立后输出 |
| --- | --- | --- | --- |
| 卡位下滑 | 查是否并发卡位异常 | 命中卡位异常 | 指向「卡位异常」待办（卡位掉→自然曝光少） |

B. 自然单↓、转化率也↓ → 链接承接/转化变差（内部）：

| 可能原因 | 验证方式 | 成立条件 | 成立后输出 |
| --- | --- | --- | --- |
| 转化率下降 | 查是否并发链接转化率异常下降 | 命中链接转化率异常下降 | 指向「链接转化率异常下降」待办 |
| 价格竞争优势下降（变化型） | 查本品+主要竞品近 7 天到手价 | 本品相对竞品变贵（本品涨/竞品降） | 监测到价格竞争优势下降：本品 ${X}→${Y}、竞品 ${Z}→${W}；请评估 |
| 非主要色链接状态异常 | 查是否并发链接状态异常（次要色/长尾色的链接不可售、Buy Box 丢失等） | 命中，作用于非主要色 / 部分子体 | 指向「链接状态」待办 |
| 库存异常（可售变体减少） | 重点查是否命中库存不足，或次要色/长尾色的FBA 可售库存为 0 | 命中，作用于部分子体 | 指向已命中的库存与可售异常具体点位处理建议（可售变体少，承接不了自然流量） |
| 新增差评（信任下降） | 查是否并发售后异常 | 命中售后异常 | 指向「售后异常」待办 |

C. 外部（竞品/市场）：

| 可能原因 | 验证方式 | 成立条件 | 成立后输出 |
| --- | --- | --- | --- |
| 市场需求整体下降 | 查直接竞品大类排名走势 | 直接竞品大类排名普遍同步下滑（非本品独有） | 监测到直接竞品大类排名普遍下滑，疑似市场需求整体下降；非本品独有，请评估 |

兜底（第一层、第二层 A/B/C 均不成立时）：提示运营核查：重要核心词的自然排名是否下滑、自然流量来源是否异常；若核心词排名下滑，建议优化 SEO/关键词布局。

输出（嵌入父卡明细）：自然流量异常作为父卡明细展开。先出第一层原因方向归类（真自然下滑/广告掩盖/增长依赖广告/广告替代）；自然单真降时，再展开第二层查证：A 入口减少、B 承接下降、C 外部市场原因（内部→需修复☐指向待办、外部→需评估◇带数据）；均不成立→兜底提示运营核查核心词自然排名。“增长依赖广告”“广告替代”给方向性处理建议。不重复父卡产品信息、优先级。

#### 6.0.9 卡位异常

前提：本查证针对已判定为卡位异常的产品（在直接竞品中排位较近 7 天下滑、达判定阈值）。卡位下滑 = 被竞品超过，原因无非两类：自己变弱、或竞品变强。直接两组都查，是哪类由查证结果自然得出（或两者都有），不预先判断。

**第一组：查自己是否变弱（指向已有异常）**

| 可能原因 | 验证方式 | 成立条件 | 成立后输出 |
| --- | --- | --- | --- |
| 销量下滑 | 查是否并发销量异常 | 命中销量异常 | 指向「销量异常」待办 |
| 转化率下降 | 查是否并发链接转化率异常下降 | 命中链接转化率异常下降 | 指向「链接转化率异常下降」待办 |
| 自然流量减少 | 查是否并发自然流量异常 | 命中自然流量异常 | 指向「自然流量异常」待办 |
| 评分/差评（信任下降） | 查是否并发售后异常 | 命中售后异常 | 指向「售后异常」待办 |
| 价格竞争优势下降（变化型） | 查本品+主要竞品近 7 天到手价 | 本品相对竞品变贵（本品涨/竞品降） | 监测到价格竞争优势下降：本品 ${X}→${Y}、竞品 ${Z}→${W}；请评估 |
| 部分变体掉线 / 部分子体库存异常 | 重点查是否命中库存不足、变体掉线，或次要色/长尾色的FBA 可售库存为 0 | 命中上述异常，且作用于部分子体 | 指向已命中的库存与可售异常或变体相关异常具体点位处理建议 |

**第二组：查竞品是否变强（提示评估）**

| 可能原因 | 验证方式 | 成立条件 | 成立后输出 |
| --- | --- | --- | --- |
| 竞品卖得越来越好 | 查直接竞品大类排名走势 | 竞品大类排名上升（竞品卖得更好） | 监测到竞品[{ASIN}]大类排名上升、卖得更好，把本品挤下；请评估竞争策略 |
| 竞品降价 | 查竞品近 7 天到手价 | 竞品降价、价格优势上升 | 监测到竞品[{ASIN}]降价（${X}→${Y}）；请评估应对（跟价/coupon） |
| 竞品上新/变体丰富 | 查竞品上新、变体数量 | 竞品近期上新或变体增多 | 监测到竞品[{ASIN}]上新/变体增多，分流了流量；请评估补齐变体/差异化 |

**兜底（两组均未命中时）：**

| 可能原因 | 验证方式 | 成立条件 | 成立后输出 |
| --- | --- | --- | --- |
| 竞品集合变化（纳入新强竞品） | 两组查证后，本品无下滑、已知竞品无动作，但卡位仍下滑 | 第一组、第二组均未命中 | 本品指标无下滑、已知竞品无明显动作，但卡位仍下滑，可能是直接竞品集合发生变化（ERP 纳入了新的更强竞品，参照系改变）；提示运营核查竞品集合近期是否新增强竞品，并人工排查卡位下滑的具体原因 |

输出（嵌入父卡明细）：卡位异常作为正式异常明细保留；若查证为本品自身变弱，则将自身变弱原因作为原因说明，并路由至已命中的具体异常点位及处理建议；若查证为竞品变强，则作为竞争环境变化提示，不生成内部修复待办。卡位异常作为父卡明细展开，两组查证结果一起呈现：自己变弱的项→“需修复”区（☐，指向已命中的具体异常点位及处理建议）、竞品变强的项→“需评估”区（◇，带竞品实际数据，提示评估）；“自己变弱”还是”竞品变强”由查证结果自然得出（哪组命中即哪类，可能两组都有命中）。两组均未命中→兜底。卡位是竞争入口层上游信号，若已连带自然流量/销量异常，在输出中标注关联。不重复父卡产品信息、优先级。

### 6.1 处理建议取用规则（三级兜底，保证正式异常有处理建议输出）

**精确匹配**：异常点位 + 严重度在下表命中 → 取该条建议。

**同点位建议补位**：异常点位已命中且 S 档已判定，但 6.2 缺少该点位对应 S 档的专属处理建议时，取该点位最接近的更严重档建议，并标注「参考同点位 SX 建议」；该补位仅用于处理建议取用，不改变原异常严重度、优先级和打分。

**大类兜底**：异常大类已识别，但具体异常点位未命中 6.2 建议表 → 保留原具体异常点位，取该大类兜底建议，并标记「大类兜底 / 建议表待补充」，定期捞出补充进表。最终输出不得只展示大类名称。

变体重要性不在本表体现：变体掉线、变体价差、库存类等已合并为单条带条件句的建议，严重度与基础分由模块 3、4.1 判定，处理建议按命中变体重要性输出对应分支。父子体关系异常按父体结构级 / 链接级处理，不参与主要色 / 次要色 / 长尾色分支。广告相关动作默认仅针对有广告投放的变体（其余颜色基本未开广告）。

### 6.2 处理建议表

## 模块 7　运营输出规范（任务卡）

前置模块 0–6 完成标签抓取、异常判定、严重度判定、优先级打分、状态流转与输出路径判断；模块 7 定义最终任务卡如何展示给运营。本模块只定义输出内容，不限定输出形态（ERP 列表页、推送通知等由实现侧决定）。

### 7.0 总则

- 以**父 ASIN 任务卡**为单位呈现：一个父 ASIN 一张卡，卡内列出该 ASIN 下全部未关闭异常明细。

- 三档执行优先级（P0/P1/P2）**展示方式统一**，不因优先级不同而改变字段结构；优先级只体现在排序与时限标识上。

- 卡内多条异常**按该条异常的执行分数从高到低排列**（贴近处理紧迫度），不按变体重要性或严重度单独排。

- 判断依据、处理建议每条异常各自携带（不同异常依据与建议不同）；初步原因 / 原因说明仅表现型异常输出，非表现型具体异常不输出原因字段。

销量增长提示与放量未执行共现去重：若”销量增长提示”与”放量未执行”同时命中，任务卡只输出”放量未执行”；销量增长数据作为该任务卡的判断依据展示，不再单独占用一条异常明细。




(7.0 中"任务卡字段标准化原则""跳过巡检时不编造表现型数据"两段为 LLM 生成行为约束,收录于知识库;字段固定输出与"待补充"占位由 7.1/7.2 渲染逻辑强制保证。)

| 当前状态 | 未处理 / 处理中 / 已处理 / 误报 / 不需处理 / 自动恢复关闭等状态 |

**C. 异常明细（每条异常一行，按该条执行分数从高到低排列）**

明细的”原因 / 处理建议”栏按异常类型展开：非表现型具体异常直接取模块 6.2 的”异常点位命中后输出”；表现型异常按模块 6.0 查因、路由和输出。若表现型异常经 6.0 查因后，真实原因指向非表现型具体异常点位，则保留原表现型异常明细，同时将该具体异常点位作为原因说明 / 处理指向，并调用模块 6.2 对应输出。若该具体点位未命中 6.2 建议表，则调用 6.3 大类兜底输出，并标记”大类兜底 / 建议表待补充”。

| 字段 | 说明 |
| --- | --- |
| 异常类型 + 问题点位 | 大类（如库存与可售）+ 具体点位（如 FBA 可售库存为 0） |
| 命中变体 + 变体重要性 | 具体子体（如黑色/M 码）+ 主要色/次要色/长尾色；链接级异常标注”链接级”（链接不可售、库存类异常均按变体级标注命中子体与变体重要性） |
| 该条严重度 | S0 / S1 / S2 |
| 作用层级 | 链接级 / 变体级 |
| 判断依据 / 数据 | 触发该异常的客观数据（如”实际 ACOS 48% vs 目标 25%，连续 4 天”） |
| 初步原因 / 原因说明（仅表现型异常） | 仅表现型异常填写，由模块 6.0 查因结果生成；非表现型具体异常不输出该字段。 |
| 处理建议 | 来自模块 6 的最终输出内容：表现型异常取 6.0 输出；非表现型具体异常取 6.2”异常点位命中后输出”；6.2 无具体点位建议时取 6.3 大类兜底输出。 |
| 上次处理记录 | 历史处理动作 + 时间（复发时尤其重要） |
| 该条执行分数 | 该异常明细对应的单异常执行分数；用于解释卡内排序，不等同于产品执行分数 |
| 复查要求 / 下一步动作 | 本条异常需要复查的时间、条件或运营下一步动作；运营设置复查时间优先 |
| 异常状态 / 操作项 | 本条异常当前状态及可执行动作，如处理、误报、不需处理、降级、转派、标记高风险 |

### 7.2 排列与归集规则

- 父卡内多条异常：按**该条异常执行分数**降序排列，最紧迫的异常排最前。

- 父卡严重度与排序解耦：父卡严重度取子异常最高（展示用），卡内排序按执行分数（紧迫度用）。

- 归集不丢信息：每条子异常的变体、变体重要性、严重度、判断依据均独立保留，不因归集到父卡而合并或丢失。

输出不丢查证结果：表现型异常的任务卡明细只输出已验证成立的原因与已排除项；内部查证动作（如”查是否并发某异常”）不得原样呈现给运营。若表现型异常经 6.0 查因后，真实原因指向非表现型具体异常点位，则本条明细保留原表现型异常，同时展示该具体异常点位作为处理指向，并调用模块 6.2 的”异常点位命中后输出”；若该点位未命中 6.2 建议表，则调用 6.3 大类兜底输出。

字段缺失处理：当 ERP、事件记忆或外部数据暂缺时，字段保留但填”待补充 / 数据不足 / 不适用”，不得删除字段；若关键字段缺失影响异常正式判定，按对应模块的数据不足规则处理。
